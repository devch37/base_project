# 11. 동적 모듈 (Dynamic Modules)

## 일반 모듈 vs 동적 모듈

```ts
// 일반 모듈: 정의가 고정
@Module({ providers: [MailerService], exports: [MailerService] })
export class MailerModule {}

// 동적 모듈: 사용하는 쪽이 "설정을 주입"
MailerModule.forRoot({ from: 'no-reply@x.com', preview: true })
```

`TypeOrmModule.forRoot(...)`, `JwtModule.register(...)`, `ConfigModule.forRoot(...)` 가
전부 동적 모듈입니다. **"설정값에 따라 프로바이더 구성이 달라지는" 모듈**이죠.

---

## 직접 만들어 보기 — `src/common/mailer/`

### 규약 (컨벤션)

| 메서드 | 용도 |
|--------|------|
| `forRoot(options)` | 동기 설정 (값을 바로 앎) |
| `forRootAsync(options)` | 비동기 설정 (다른 프로바이더에 의존) |
| `forFeature(...)` | 하위 기능 등록 (예: `TypeOrmModule.forFeature([Entity])`) |

### `mailer.module.ts`

```ts
@Global()          // 앱 어디서든 MailerService 주입 가능 (남용 금지)
@Module({})
export class MailerModule {
  static forRoot(options: MailerOptions): DynamicModule {
    return {
      module: MailerModule,
      providers: [
        { provide: MAILER_OPTIONS, useValue: options },   // 설정을 프로바이더로
        MailerService,
      ],
      exports: [MailerService],
    };
  }

  static forRootAsync(options: MailerAsyncOptions): DynamicModule {
    return {
      module: MailerModule,
      imports: options.imports ?? [],
      providers: [
        {
          provide: MAILER_OPTIONS,
          useFactory: options.useFactory,   // ConfigService 등을 받아 옵션 생성
          inject: options.inject ?? [],
        },
        MailerService,
      ],
      exports: [MailerService],
    };
  }
}
```

핵심: **설정값(`MAILER_OPTIONS`)을 프로바이더로 등록**하면, `MailerService` 가 그걸 주입받습니다.

### `mailer.service.ts`

```ts
@Injectable()
export class MailerService {
  constructor(@Inject(MAILER_OPTIONS) private readonly options: MailerOptions) {}

  async send(payload: SendMailPayload) {
    if (this.options.preview) { /* 콘솔 출력만 */ }
    else { /* 실제 SMTP */ }
  }
}
```

### 사용 — `app.module.ts`

```ts
MailerModule.forRootAsync({
  inject: [ConfigService],
  useFactory: (cfg: ConfigService) => ({
    from: 'no-reply@nestjs-tutorial.local',
    preview: cfg.get('app.env') !== 'production',   // 개발이면 콘솔만
  }),
}),
```

`auth.service.ts` 가 `MailerService` 를 주입받아 회원가입 시 환영 메일을 "보냅니다"
(개발 모드라 콘솔에 출력됨 — 로그 확인).

## `ConfigurableModuleBuilder` — 보일러플레이트 자동화

위 `forRoot`/`forRootAsync` 를 손으로 쓰는 게 반복적이라, NestJS가 빌더를 제공합니다:

```ts
// mailer.module-definition.ts
import { ConfigurableModuleBuilder } from '@nestjs/common';

export const { ConfigurableModuleClass, MODULE_OPTIONS_TOKEN } =
  new ConfigurableModuleBuilder<MailerOptions>()
    .setClassMethodName('forRoot')   // 메서드 이름 지정
    .build();

// mailer.module.ts
@Module({ providers: [MailerService], exports: [MailerService] })
export class MailerModule extends ConfigurableModuleClass {}
//                        ↑ forRoot / forRootAsync 가 자동 생성됨
```

`MODULE_OPTIONS_TOKEN` 을 `@Inject` 하면 설정을 받습니다. 신규 코드는 이 방식을 권장.
(이 프로젝트는 "동적 모듈의 원리"를 보여주려고 수동 버전을 남겨 뒀습니다.)

---

## `@Global()` 을 언제 쓰나

- ✅ 진짜 모든 곳에서 필요한 것: 설정, 로거, DB 커넥션, 해싱
- ❌ 그 외 전부 — `imports` 로 명시적으로 연결하세요. 전역은 "누가 이걸 쓰는지"를
  코드에서 감춥니다.

이 프로젝트의 전역 모듈: `ConfigModule`, `CacheModule`, `HashingModule`, `MailerModule`.
