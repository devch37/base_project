# 03. 요청 라이프사이클 — 미들웨어 · 가드 · 인터셉터 · 파이프 · 필터

NestJS 요청은 정해진 순서로 여러 관문을 통과합니다. **이 순서를 외우면 디버깅이 쉬워집니다.**

```
요청 들어옴
  │
  ▼
① 미들웨어 (Middleware)            ─ helmet, compression, cors, 로깅
  │
  ▼
② 가드 (Guard)                     ─ 인증/인가. "들여보낼까 말까?" → false면 403/401
  │                                   순서: ThrottlerGuard → JwtAuthGuard → RolesGuard
  ▼
③ 인터셉터 (전반부, Interceptor)   ─ next.handle() 호출 전
  │
  ▼
④ 파이프 (Pipe)                    ─ @Body/@Param/@Query 값 검증·변환 (ValidationPipe)
  │
  ▼
⑤ 컨트롤러 핸들러 → 서비스          ─ 실제 비즈니스 로직
  │
  ▼
⑥ 인터셉터 (후반부)                ─ 응답 변형 (TransformInterceptor 가 봉투로 감쌈)
  │
  ▼
⑦ 예외 필터 (Exception Filter)     ─ 위 어디서든 에러가 나면 여기로 점프
  │
  ▼
응답 나감
```

각각을 이 프로젝트의 실제 파일과 함께 봅니다.

---

## ① 미들웨어

가장 낮은 수준(Express 레벨). `main.ts` 에서 적용:

```ts
app.use(helmet());        // 보안 HTTP 헤더
app.use(compression());   // 응답 gzip 압축
app.enableCors({ ... });  // CORS
```

Nest 방식 미들웨어(클래스)는 `configure(consumer)` 로 등록하지만,
대부분 위처럼 함수형으로 충분합니다.

**미들웨어 vs 인터셉터**: 미들웨어는 라우트 핸들러/DI 컨텍스트를 모릅니다.
"이 요청이 어떤 컨트롤러로 갈지" 알아야 하면 인터셉터/가드를 쓰세요.

---

## ② 가드 (Guard) — "통과 여부"

`CanActivate` 를 구현하고 `boolean` 을 반환합니다. `false` → 요청 차단.

`src/common/guards/jwt-auth.guard.ts`:
```ts
@Injectable()
export class JwtAuthGuard extends AuthGuard('jwt') {
  canActivate(context: ExecutionContext) {
    // @Public() 이 붙었으면 통과
    const isPublic = this.reflector.getAllAndOverride(IS_PUBLIC_KEY, [
      context.getHandler(), context.getClass(),
    ]);
    if (isPublic) return true;
    return super.canActivate(context);  // 아니면 JWT 검증
  }
}
```

`app.module.ts` 에서 **전역 등록** (순서가 곧 실행 순서):
```ts
{ provide: APP_GUARD, useClass: ThrottlerGuard },  // 1. 요청 수 제한
{ provide: APP_GUARD, useClass: JwtAuthGuard },    // 2. 인증
{ provide: APP_GUARD, useClass: RolesGuard },      // 3. 인가
```

→ 자세한 인증/인가는 06, 07장.

## ③⑥ 인터셉터 (Interceptor) — "요청 전후를 감싼다" (AOP)

RxJS `Observable` 을 다룹니다. `next.handle()` 이 "핸들러 실행"을 의미.

### 응답 표준화 — `src/common/interceptors/transform.interceptor.ts`

컨트롤러는 순수 데이터만 반환:
```ts
return this.postsService.findAll(query);  // Post[] 또는 { items, meta }
```
인터셉터가 봉투를 씌움:
```json
{ "success": true, "data": [...], "meta": {...}, "timestamp": "...", "path": "/api/posts" }
```

### 로깅 — `src/common/interceptors/logging.interceptor.ts`

`tap()` 으로 부수효과(로그)만 실행, 응답은 건드리지 않음:
```
[HTTP] GET /api/posts 200 +23ms
```

### 타임아웃 — `src/common/interceptors/timeout.interceptor.ts`

`timeout(ms)` 로 오래 걸리는 요청을 `408 Request Timeout` 으로 강제 종료.

**전역 등록 순서 주의**: `app.module.ts` 에서 `LoggingInterceptor` → `TransformInterceptor`
순으로 등록하면, 요청은 그 순서로, **응답은 역순**으로 통과합니다.

## ④ 파이프 (Pipe) — "입력값 검증·변환"

핸들러 파라미터에 값이 도달하기 직전에 실행됩니다.

### 내장 파이프

```ts
@Param('id', ParseIntPipe) id: number   // "3"(string) → 3(number), 실패 시 400
@Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number
```

### 전역 ValidationPipe — `main.ts`

```ts
app.useGlobalPipes(new ValidationPipe({
  whitelist: true,              // DTO에 없는 속성 제거
  forbidNonWhitelisted: true,   // 없는 속성 오면 400
  transform: true,              // 평범한 객체 → DTO 클래스 인스턴스
  transformOptions: { enableImplicitConversion: true },
}));
```

이게 `class-validator` 데코레이터(`@IsEmail()` 등)를 실제로 실행시키는 주체입니다.
→ 04장에서 DTO와 함께 자세히.

### 커스텀 파이프

`PipeTransform` 을 구현하면 됩니다. 예: 문자열을 특정 enum으로만 허용:
```ts
@Injectable()
export class ParseRolePipe implements PipeTransform {
  transform(value: string) {
    if (!Object.values(Role).includes(value as Role))
      throw new BadRequestException('알 수 없는 역할');
    return value as Role;
  }
}
```

## ⑦ 예외 필터 (Exception Filter) — "에러를 응답으로"

`src/common/filters/all-exceptions.filter.ts` 가 **모든 예외**를 잡아
하나의 표준 형태로 변환합니다:

```ts
@Catch()  // 인자 없음 = 모든 예외
export class AllExceptionsFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    // HttpException → 그대로
    // TypeORM QueryFailedError(UNIQUE 위반) → 409
    // 그 외 → 500 (내부 사정은 로그에만)
  }
}
```

→ 08장에서 에러 처리 전략을 자세히.

## 적용 범위: 전역 vs 컨트롤러 vs 핸들러

| 범위 | 방법 | DI 주입 |
|------|------|---------|
| 전역 (프로바이더) | `app.module.ts` 의 `APP_GUARD`/`APP_INTERCEPTOR`/`APP_FILTER` | ✅ 완전 |
| 전역 (인스턴스) | `main.ts` 의 `app.useGlobalXxx(new Xxx())` | ❌ 제한적 |
| 컨트롤러 | `@UseGuards(X)` / `@UseInterceptors(X)` 를 클래스에 |  ✅ |
| 핸들러 | 같은 데코레이터를 메서드에 | ✅ |

**규칙**: DI가 필요하면 (다른 서비스를 주입받아야 하면) `app.module.ts` 의 `APP_*` 토큰을 쓰세요.
