# 13. 실무 체크리스트와 배포

"좋은 백엔드 엔지니어"가 신경 쓰는 것들. 이 프로젝트가 이미 한 것(✅)과 실무에서 더 해야 할 것(➕).

---

## 보안

- ✅ `helmet()` — 보안 HTTP 헤더 (`main.ts`)
- ✅ 전역 인증 가드 + `@Public()` 화이트리스트
- ✅ 비밀번호 bcrypt 해시, `select: false`
- ✅ refresh 토큰은 해시로 저장 + 회전
- ✅ 계정 열거 방지 (로그인 실패 메시지 통일)
- ✅ `ValidationPipe` `whitelist` — 예상 못한 필드 차단
- ✅ Rate limiting (`@nestjs/throttler`)
- ✅ 에러 응답에서 내부 정보 은닉 (`AllExceptionsFilter`)
- ➕ **CORS `origin` 을 실제 도메인으로 좁히기** (지금은 개발용 `true`)
- ➕ `/auth/*` 에 더 강한 rate limit
- ➕ 시크릿을 시크릿 매니저로 (지금은 `.env`)
- ➕ SQL: 항상 파라미터 바인딩 (이 프로젝트는 지킴), ORM raw 쿼리 주의
- ➕ 의존성 취약점 스캔 (`npm audit`, Snyk, Dependabot)
- ➕ 요청 본문 크기 제한 (`app.use(json({ limit: '1mb' }))`)
- ➕ HTTPS 종단 (보통 로드밸런서/리버스 프록시에서)

## 배포

### 빌드 & 실행

```bash
npm ci                     # 잠금 파일 기준 설치 (npm install 아님)
npm run build              # dist/ 생성
NODE_ENV=production node dist/main.js
```

### Dockerfile (멀티스테이지)

```dockerfile
# --- build ---
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build && npm prune --production

# --- runtime ---
FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/node_modules ./node_modules
COPY --from=build /app/dist ./dist
COPY package.json ./
USER node
EXPOSE 3000
CMD ["node", "dist/main.js"]
```

> `better-sqlite3` 는 네이티브 모듈이라 alpine에서 빌드 도구가 필요할 수 있습니다
> (`apk add --no-cache python3 make g++`). 운영 DB는 보통 PostgreSQL이므로 이 이슈는 사라집니다.

### 컨테이너 헬스체크 → k8s

```yaml
livenessProbe:
  httpGet: { path: /api/health, port: 3000 }
readinessProbe:
  httpGet: { path: /api/health/ready, port: 3000 }   # DB까지 확인
```

### 마이그레이션은 배포 파이프라인의 별도 단계

```
빌드 → 이미지 푸시 → [마이그레이션 실행] → 롤링 배포
```
앱 시작 시 자동 실행(`migrationsRun`)은 인스턴스가 여러 개면 경합이 생깁니다.

### 환경변수 체크리스트 (운영)

```
NODE_ENV=production
DB_SYNCHRONIZE=false        ← 필수
JWT_ACCESS_SECRET=<32+ 랜덤>
JWT_REFRESH_SECRET=<32+ 랜덤, access와 다르게>
THROTTLE_LIMIT=<적절히>
CORS 도메인 화이트리스트
```

## PostgreSQL로 전환하기 (실무 대비)

1. `npm i pg && npm rm better-sqlite3 @types/better-sqlite3`
2. `typeorm.config.ts` / `data-source.ts` 의 `type: 'better-sqlite3'` → `'postgres'`,
   `database` 대신 `host/port/username/password/database`
3. `AllExceptionsFilter` 의 UNIQUE 위반 감지 정규식을 Postgres 에러 코드(`23505`)로 변경
4. 마이그레이션 새로 생성 (SQLite와 DDL이 다름)

나머지 코드(엔티티, 서비스, Repository API)는 **그대로**입니다. ORM 추상화의 이점.

## 마무리

좋은 백엔드 엔지니어의 습관:
1. **경계를 명확히** — 모듈, DTO/엔티티, 컨트롤러/서비스
2. **실패를 설계** — 어떤 에러가 나고, 클라이언트가 뭘 보고, 로그에 뭐가 남는지
3. **관측 가능하게** — 안 보이면 고칠 수 없다
4. **테스트로 규칙을 고정** — 리팩터링이 두렵지 않게
5. **설정은 환경에, 시크릿은 안전하게**
