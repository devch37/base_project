# 00. 환경 설정과 첫 실행

## NestJS 한 문장 요약

> **NestJS = "구조를 강제하는" Node.js 백엔드 프레임워크.**
> Express(또는 Fastify) 위에서 동작하며, Angular에서 영감을 받은
> **모듈 / 의존성 주입 / 데코레이터** 체계로 대규모 앱을 일관되게 만들 수 있습니다.

Express만 쓰면 폴더 구조, DI, 검증, 에러 처리 방식이 팀마다 제각각입니다.
NestJS는 이걸 표준화해서 "어느 회사 NestJS 코드든 비슷하게 읽힌다"는 이점을 줍니다.

## 사전 준비

- Node.js 20 이상 (`node -v`)
- 이 프로젝트는 추가 인프라(DB 서버, Redis 등) 없이 **SQLite 파일 DB**로 동작합니다.

## 설치 & 실행

```bash
cd nestjs-tutorial
npm install
cp .env.example .env      # 환경변수 파일 생성
npm run seed              # 예제 데이터 삽입 (선택)
npm run start:dev         # 개발 서버 (파일 변경 시 자동 재시작)
```

- API: http://localhost:3000/api
- **Swagger 문서: http://localhost:3000/api/docs** ← 여기서 모든 API를 눌러볼 수 있습니다
- 헬스체크: http://localhost:3000/api/health

시드로 만들어진 계정: `admin@example.com` / `alice@example.com` / `bob@example.com` (비밀번호 `Passw0rd!`)

## 프로젝트 구조

```
src/
├─ main.ts                  # 부트스트랩(진입점): 전역 설정, 미들웨어, Swagger
├─ app.module.ts            # 루트 모듈 — 모든 모듈을 조립
├─ app.controller.ts        # 루트 라우트(/api)
│
├─ config/                  # 환경변수 로딩 + 검증 (04, 09장)
│  ├─ configuration.ts
│  └─ env.validation.ts
│
├─ database/                # TypeORM 설정, 마이그레이션, 시드 (05장)
│  ├─ data-source.ts        # CLI 전용 DataSource
│  ├─ typeorm.config.ts     # 런타임 설정 팩토리
│  └─ seeds/
│
├─ common/                  # 여러 모듈이 공유하는 횡단 관심사 (03, 07, 08, 11장)
│  ├─ decorators/           # @Public, @Roles, @CurrentUser
│  ├─ dto/                  # 페이지네이션
│  ├─ entities/             # BaseEntity (id, createdAt, updatedAt)
│  ├─ enums/                # Role
│  ├─ filters/              # 전역 예외 필터
│  ├─ guards/               # JwtAuthGuard, RolesGuard
│  ├─ interceptors/         # 응답 표준화, 로깅, 타임아웃
│  ├─ hashing/              # 비밀번호 해싱 서비스 (전역 모듈)
│  └─ mailer/               # 동적 모듈 예제
│
└─ modules/                 # 도메인(비즈니스) 모듈
   ├─ users/                # 사용자 CRUD
   ├─ auth/                 # 회원가입/로그인/토큰 갱신 (06장)
   ├─ posts/                # 게시글 + 태그(N:M), 검색/페이지네이션
   ├─ comments/             # 댓글 (중첩 라우팅)
   ├─ health/               # 헬스체크
   └─ tasks/                # 스케줄러 예제 (10장)
```

## 이 튜토리얼이 만드는 것

**게시판 API**입니다. 도메인은 단순하지만 실무의 핵심 요소를 모두 담았습니다:

| 요소 | 어디서 배우나 |
|------|--------------|
| 모듈/DI/데코레이터 | 01, 02장 |
| 요청 파이프라인 (파이프·가드·인터셉터·필터) | 03장 |
| DTO 검증 | 04장 |
| DB (엔티티, 관계, 트랜잭션, 마이그레이션) | 05장 |
| 인증 (JWT access/refresh, Passport) | 06장 |
| 인가 (RBAC, 소유권, 커스텀 데코레이터) | 07장 |
| 에러 처리 & 로깅 | 08장 |
| 설정 관리 | 09장 |
| 캐싱 / 스케줄러 / rate limiting | 10장 |
| 동적 모듈 | 11장 |
| 테스트 (unit + e2e) | 12장 |
| 배포 체크리스트 | 13장 |

## 핵심 명령어

```bash
npm run start:dev      # 개발 서버 (watch)
npm run build          # dist/ 로 컴파일
npm run start:prod     # 컴파일된 결과 실행
npm test               # 단위 테스트
npm run test:e2e       # e2e 테스트
npm run lint           # ESLint
npm run seed           # 예제 데이터
npm run migration:generate -- src/database/migrations/이름   # 마이그레이션 생성
npm run migration:run  # 마이그레이션 적용
```
