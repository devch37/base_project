# 09. 설정과 환경변수

## 원칙 (12-Factor App)

> **설정은 코드가 아니라 "환경"에 둔다.**
> DB 주소, 시크릿, 외부 API 키는 `.env`(로컬) / 시크릿 매니저(운영)로 주입.
> 코드에는 절대 하드코딩하지 않는다. (`.env` 는 `.gitignore` 에)

---

## 3단계 구조

```
.env  ──①읽기──►  ConfigModule  ──②검증──►  Joi 스키마  ──③구조화──►  configuration.ts
                                                                          │
                                                              @Inject(xxxConfig.KEY)
                                                                          ▼
                                                                     서비스에서 사용
```

### ① `.env` — `.env.example` 을 복사해서 만듦

```bash
cp .env.example .env
```
`.env.example` 은 커밋합니다 (어떤 키가 필요한지 문서 역할). `.env` 는 커밋 안 함.

### ② 부팅 시 검증 — `src/config/env.validation.ts`

```ts
export const validationSchema = Joi.object({
  NODE_ENV: Joi.string().valid('development', 'production', 'test').default('development'),
  PORT: Joi.number().default(3000),
  JWT_ACCESS_SECRET: Joi.string().min(8).required(),   // 없으면 서버가 안 뜸
  // ...
});
```

`app.module.ts`:
```ts
ConfigModule.forRoot({
  isGlobal: true,
  load: configurations,
  validationSchema,
  validationOptions: { abortEarly: false },   // 에러를 한 번에 다 보여줌
})
```

**왜 부팅 시 검증?** → 필수 env가 빠졌을 때, 운영 중 특정 요청에서 `undefined` 로
터지는 것보다 "서버가 아예 안 뜨는" 게 훨씬 낫습니다. 배포 즉시 알 수 있으니까요.

### ③ 타입 있는 구조화 — `src/config/configuration.ts`

```ts
export const jwtConfig = registerAs('jwt', () => ({
  accessSecret: process.env.JWT_ACCESS_SECRET ?? 'dev-access-secret',
  accessExpiresIn: process.env.JWT_ACCESS_EXPIRES_IN ?? '15m',
  refreshSecret: process.env.JWT_REFRESH_SECRET ?? 'dev-refresh-secret',
  refreshExpiresIn: process.env.JWT_REFRESH_EXPIRES_IN ?? '7d',
}));
```

`registerAs('jwt', ...)` = "jwt" 네임스페이스로 등록. 문자열을 숫자/불리언으로 변환하는 것도 여기서.

## 주입해서 쓰기 — 두 가지 방법

### 방법 A: `ConfigService` (간단, 문자열 키)

```ts
constructor(private readonly config: ConfigService) {}

const ttl = this.config.get<number>('cache.ttl', 5000);   // 기본값 지정 가능
```
`app.module.ts` 의 `CacheModule`, `ThrottlerModule` 이 이 방식.

### 방법 B: `ConfigType` + `KEY` (타입 안전, 권장)

```ts
import { ConfigType } from '@nestjs/config';
import { jwtConfig } from '../../config/configuration';

constructor(
  @Inject(jwtConfig.KEY)
  private readonly cfg: ConfigType<typeof jwtConfig>,   // ← 자동완성 됨!
) {}

this.cfg.accessSecret;   // string 으로 타입 추론
```
`jwt.strategy.ts`, `auth.service.ts` 가 이 방식. **오타가 컴파일 에러로 잡힙니다.**

## 비동기 설정 (`forRootAsync`)

모듈이 `ConfigService` 에 의존해서 설정을 만들어야 할 때:

```ts
// app.module.ts
TypeOrmModule.forRootAsync({ useClass: TypeOrmConfigService }),

// database/typeorm.config.ts
@Injectable()
export class TypeOrmConfigService implements TypeOrmOptionsFactory {
  constructor(private readonly config: ConfigService) {}
  createTypeOrmOptions(): TypeOrmModuleOptions {
    return {
      type: 'better-sqlite3',
      database: this.config.get('database.database'),
      synchronize: this.config.get('database.synchronize') && !isProd,
    };
  }
}
```

`useFactory` 버전도 가능 (더 짧을 때):
```ts
CacheModule.registerAsync({
  inject: [ConfigService],
  useFactory: (cfg: ConfigService) => ({ ttl: cfg.get('cache.ttl') }),
})
```

## 환경별 파일

```ts
ConfigModule.forRoot({
  envFilePath: [`.env.${process.env.NODE_ENV}`, '.env'],  // 앞이 우선
})
```
`.env.development`, `.env.test`, `.env.production` 을 분리할 수 있습니다.
(단, 운영 시크릿은 파일이 아니라 시크릿 매니저로!)

---

## 운영에서의 시크릿 관리

| 환경 | 방법 |
|------|------|
| 로컬 | `.env` 파일 |
| CI | CI 시스템의 Secrets (GitHub Actions Secrets 등) |
| 컨테이너/k8s | `Secret` 리소스 → 환경변수 또는 볼륨 마운트 |
| 클라우드 | AWS Secrets Manager, GCP Secret Manager, HashiCorp Vault |

핵심: **코드는 `process.env` 만 읽는다.** 값이 어디서 오는지는 배포 환경이 결정.
