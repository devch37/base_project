# 14. 함수 포인터와 제네릭 프로그래밍

> 목표: 함수 포인터 타입을 **읽고 쓰기**, 콜백 패턴, `qsort`/`bsearch`,
> `void *` 로 타입을 지워 **하나의 코드로 모든 타입**을 다루기.

---

## 0. 초등학생 버전 비유

함수 포인터는 **"리모컨 버튼에 기능을 나중에 배정하는 것"** 입니다.

TV 리모컨에 빈 버튼이 있어요. 여기에 "넷플릭스 켜기"를 넣을 수도, "유튜브 켜기"를 넣을 수도 있죠.
버튼(호출하는 쪽 코드)은 그대로인데, **누르면 무슨 일이 일어날지는 나중에 정합니다.**

`qsort` 가 딱 이겁니다: "정렬은 내가 할 테니, **두 원소 중 뭐가 먼저인지 판단하는 법**은
네가 함수로 알려줘."

## 1. 함수 포인터 선언 읽기

```c
int add(int a, int b) { return a + b; }

int (*fp)(int, int);          // fp: "int 2개를 받아 int 를 반환하는 함수로의 포인터"
fp = add;                     // 함수 이름은 자동으로 주소로 붕괴 (&add 도 됨)
fp = &add;                    // 동일
int r = fp(2, 3);             // 호출. (*fp)(2, 3) 도 동일
```

### 괄호가 핵심
```c
int (*fp)(int);               // 포인터 to 함수
int *fp(int);                 // 함수 returning int*  ← 완전히 다름!
```

### typedef 로 읽기 쉽게 (실무 필수)
```c
typedef int (*BinOp)(int, int);      // BinOp = "int,int -> int" 함수 포인터 타입
BinOp op = add;
void register_handler(BinOp fn);     // 시그니처가 명확
```

`./bin/14_callbacks` 가 계산기 디스패치 테이블로 이걸 보여 줍니다.

## 2. 콜백 패턴

"내가 순회할 테니, 각 원소로 뭘 할지는 네가 정해":

```c
void array_foreach(int *a, size_t n, void (*fn)(int value, void *ctx), void *ctx) {
    for (size_t i = 0; i < n; i++) fn(a[i], ctx);
}

// 사용
static void accumulate(int v, void *ctx) { *(long *)ctx += v; }

long sum = 0;
array_foreach(arr, n, accumulate, &sum);
```

- **`void *ctx` 관용구**: 콜백에 "추가 상태"를 넘기는 표준 방법. C엔 클로저가 없으므로
  캡처할 변수를 구조체에 담아 `ctx` 로 전달합니다.
- 콜백 시그니처에 `ctx` 를 안 넣은 API(예: `qsort`)는 전역 변수에 의존해야 해서 불편합니다.
  그래서 `qsort_r`(BSD/GNU, 시그니처가 서로 다름) 이나 `qsort_s`(C11 부록 K) 가 생겼습니다.

## 3. `qsort` / `bsearch` 정확히 쓰기

```c
#include <stdlib.h>
void qsort(void *base, size_t n, size_t size,
           int (*cmp)(const void *, const void *));
void *bsearch(const void *key, const void *base, size_t n, size_t size,
              int (*cmp)(const void *, const void *));
```

- `cmp(a, b)` 는 `a<b` 면 음수, 같으면 0, `a>b` 면 양수를 반환.
- **`return *a - *b;` 는 버그**입니다 — 정수 오버플로우 가능. 이렇게:
  ```c
  int cmp_int(const void *pa, const void *pb) {
      int a = *(const int *)pa, b = *(const int *)pb;
      return (a > b) - (a < b);        // -1, 0, 1 을 오버플로우 없이
  }
  ```
- 구조체 배열 정렬:
  ```c
  int cmp_by_age(const void *pa, const void *pb) {
      const Person *a = pa, *b = pb;
      return (a->age > b->age) - (a->age < b->age);
  }
  qsort(people, n, sizeof people[0], cmp_by_age);
  ```
- 문자열 배열(`char *arr[]`) 정렬: 원소가 `char *` 이므로 `cmp` 인자는 `char **`:
  ```c
  int cmp_str(const void *pa, const void *pb) {
      return strcmp(*(const char **)pa, *(const char **)pb);
  }
  ```
- `qsort` 는 **불안정 정렬**(같은 키의 상대 순서 안 지킴). 안정성이 필요하면 인덱스를 tiebreak로.

## 4. `void *` 로 제네릭 컨테이너 만들기

타입을 지운 동적 배열:

```c
typedef struct {
    void  *data;
    size_t len, cap, elem_size;      // elem_size 로 "한 칸"의 크기를 기억
} GVec;

int gvec_push(GVec *v, const void *elem) {
    if (v->len == v->cap) { /* realloc: cap * elem_size 바이트 */ }
    memcpy((char *)v->data + v->len * v->elem_size, elem, v->elem_size);
    v->len++;
    return 0;
}

void *gvec_at(GVec *v, size_t i) {
    return (char *)v->data + i * v->elem_size;   // char* 로 캐스트해 바이트 산술
}
```

`./bin/14_generic_vec` 가 이걸 `int` 와 구조체로 함께 씁니다.

### `void *` 방식의 대가
- **타입 안전성 없음**: `int` 벡터에 `double` 을 push해도 컴파일러가 안 막음.
- **간접 참조 비용**: `memcpy`, 캐스트, 캐시 비친화.
- 그래서 대안:
  - **매크로 제네릭** (`#define VEC_DEFINE(T)` 로 타입별 코드 생성) — `stb`, `klib` 스타일.
  - `_Generic` (C11): 컴파일 타임 타입 분기.
    ```c
    #define print(x) _Generic((x), int: print_int, double: print_double, char *: print_str)(x)
    ```

## 5. 상태 기계 / 디스패치 테이블

```c
typedef void (*Handler)(Event *);

static const Handler table[EVENT_COUNT] = {
    [EVENT_CONNECT]    = on_connect,
    [EVENT_DATA]       = on_data,
    [EVENT_DISCONNECT] = on_disconnect,
};

void dispatch(Event *e) {
    if (e->type < EVENT_COUNT && table[e->type])
        table[e->type](e);
}
```

`switch` 보다 확장 쉽고, 런타임에 핸들러 교체 가능(플러그인). 인터프리터, 이벤트 루프,
프로토콜 파서에서 흔합니다.
