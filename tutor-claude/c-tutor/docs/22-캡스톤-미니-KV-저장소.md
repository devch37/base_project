# 22. 캡스톤: 미니 키-값 저장소

> 목표: 00~21장에서 배운 것을 **하나의 실전 프로그램**으로 통합한다.
> 결과물: 디스크에 영속되는 key-value 저장소 CLI (`kv`).

코드: `capstone/` (독립 빌드). `Makefile` 과 `CMakeLists.txt` 를 모두 제공합니다.

---

## 0. 무엇을 만드나

```bash
cd capstone
make                       # 또는: cmake -S . -B build && cmake --build build

./bin/kv set name alice
./bin/kv set lang C
./bin/kv get name          # alice
./bin/kv list              # name=alice  lang=C
./bin/kv del lang
./bin/kv get lang          # (없음), 종료 코드 1
./bin/kv compact           # 로그 파일에서 죽은 레코드 제거
make test                  # 단위 테스트
```

데이터는 `store.db` (append-only 로그)에 저장됩니다. 프로그램을 껐다 켜도 유지됩니다.

---

## 1. 설계 — "append-only 로그 + 인메모리 인덱스"

실제 DB(Bitcask, LevelDB, Redis AOF)가 쓰는 구조의 축소판입니다.

```
디스크: store.db  (append-only, 절대 중간을 수정하지 않음)
  ┌──────────────────────────────────────────────┐
  │ rec: [magic][op=SET][klen][k][vlen][v][crc]   │
  │ rec: [magic][op=SET][klen][k][vlen][v][crc]   │
  │ rec: [magic][op=DEL][klen][k][0][crc]         │  ← 삭제도 "삭제 레코드를 추가"
  │ rec: [magic][op=SET][klen][k][vlen][v][crc]   │  ← 같은 키 재설정 = 새 레코드
  └──────────────────────────────────────────────┘

메모리: HashMap<string, string>   (시작 시 로그를 처음부터 재생해서 구축)
```

### 왜 이렇게?
- **append-only**: 쓰기가 항상 파일 끝 → 빠르고, 크래시에 강함(부분 쓰인 마지막 레코드만 버리면 됨).
- **인메모리 인덱스**: 읽기는 해시맵 조회라 O(1). 디스크를 안 뒤짐.
- **compact**: 로그가 커지면(같은 키를 여러 번 set) 인덱스를 새 로그로 다시 쓰기.

### 각 장이 어디에 쓰이나

| 장 | 캡스톤에서 |
|----|-----------|
| 02, 16 | 레코드 길이 필드를 `uint32_t` 로, 엔디언 무관 직렬화(`put_u32_be`) |
| 06, 08 | 문자열 소유권: 인덱스가 키/값을 복사·소유, `free` 짝 맞추기 |
| 09 | 레코드 구조체, op 열거형 |
| 11 | `kvstore.h` 불투명 포인터 (`typedef struct KvStore KvStore;`) |
| 13 | `fopen`/`fread`/`fwrite`, `errno`, `goto cleanup` 로 로드 함수 |
| 14, 15 | 해시맵(체이닝, FNV-1a), 재생 로직 |
| 12 | `strtol` 없이도 CLI 인자 파싱, `snprintf` |
| 17 | `make asan`, `make leaks` 로 누수 0 검증 |
| 20 | 입력 길이 검사(레코드 klen/vlen 을 믿지 않고 파일 크기와 대조), 정수 오버플로우 방어 |
| 18, 21 | Makefile + CMake, 테스트, 스타일 |

## 3. 공개 API (`kvstore.h`)

```c
typedef struct KvStore KvStore;

typedef enum {
    KV_OK = 0,
    KV_ERR_IO = -1,
    KV_ERR_NOMEM = -2,
    KV_ERR_CORRUPT = -3,
    KV_ERR_NOTFOUND = -4,
    KV_ERR_BADKEY = -5,
} KvResult;

KvStore    *kv_open(const char *path);          // 로그 열기/생성 + 재생. 실패 시 NULL
void        kv_close(KvStore *s);

KvResult    kv_set(KvStore *s, const char *key, const char *value);
KvResult    kv_get(KvStore *s, const char *key, char **out_value);  // *out_value: 호출자 free
KvResult    kv_del(KvStore *s, const char *key);
size_t      kv_count(const KvStore *s);
KvResult    kv_foreach(KvStore *s, void (*fn)(const char *k, const char *v, void *), void *ctx);
KvResult    kv_compact(KvStore *s);             // 죽은 레코드 제거

const char *kv_strerror(KvResult r);
```

이 시그니처만 봐도 06(이중 포인터 out), 08(소유권), 11(불투명), 13(에러 코드),
14(콜백+ctx) 이 다 들어 있는 게 보입니다.

## 4. 직접 해 볼 구현 순서 (막히면 `src/` 정답 참고)

1. `serialize.h`: `put_u32_be`, `get_u32_be`, `crc32` (16장 예제 재사용).
2. `hashmap.h`: 15장 해시맵을 값 타입 `char *` 로 바꾸고, 갱신 시 옛 값 `free`.
3. `kvstore.c` `kv_open`: 파일 없으면 생성. 있으면 레코드를 하나씩 읽어 인덱스 구축.
   - 손상된/잘린 마지막 레코드는 **버리고** 파일을 그 지점까지 truncate (크래시 복구).
4. `kv_set`: 인덱스 갱신 + 로그에 SET 레코드 append + `fflush`.
5. `kv_get`: 인덱스 조회, 값 복사해서 반환.
6. `kv_del`: 인덱스에서 제거 + DEL 레코드 append.
7. `kv_compact`: 새 임시 파일에 현재 인덱스를 SET 레코드로 다 쓰고, `rename` 으로 교체.
8. `main.c`: `argv` 파싱, 명령 디스패치, 종료 코드.
9. `test_kvstore.c`: set/get/del/재오픈 후 유지/compact 시나리오.

## 6. 확장 과제 (실무 감각 키우기)

- **TTL**: 레코드에 만료 시각 필드 추가, `kv_get` 시 만료 확인.
- **범위 조회**: 인덱스를 정렬된 배열로도 유지해 `kv scan <prefix>`.
- **동시성**: `kv_set` 을 여러 스레드에서 호출해도 안전하게 (19장, mutex 또는 단일 writer 스레드).
- **바이너리 값**: 값에 `\0` 이 들어가도 되게 (지금은 문자열 가정).
- **mmap**: 재생 대신 `mmap` 으로 로그를 읽기.
- **네트워크**: `kv serve` 로 TCP 서버(소켓)를 열어 여러 클라이언트 처리.
