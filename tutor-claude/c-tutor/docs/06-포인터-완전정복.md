# 06. 포인터 완전 정복

> 이 코스에서 가장 중요한 장입니다. 천천히, 두 번 읽으세요.
> 목표: 포인터의 정확한 의미, `&`/`*`, `const` 위치, `NULL`, 이중 포인터, `void *`.

---

## 0. 초등학생 버전 비유

아파트 단지를 생각하세요.
- **변수** = 집. 안에 물건(값)이 들어 있어요.
- **주소** = 그 집의 동·호수. "101동 302호".
- **포인터** = 동·호수가 적힌 쪽지. 쪽지 자체도 어딘가(다른 집)에 보관돼요.
- `&x` = "x라는 집의 동·호수를 알려줘"
- `*p` = "이 쪽지에 적힌 집에 가서, 그 안의 물건을 꺼내(또는 넣어)"
- `NULL` = 아무것도 안 적힌 빈 쪽지. 이걸 들고 집을 찾아가면(`*NULL`) → 사고(크래시).

포인터가 어려운 이유는 **"쪽지"와 "쪽지가 가리키는 집"을 자꾸 헷갈리기 때문**입니다.
`p` 를 바꾸는 것과 `*p` 를 바꾸는 것은 완전히 다릅니다.

---

## 1. 선언 읽는 법

```c
int   x = 10;      // x 는 int
int  *p;           // p 는 "int 를 가리키는 포인터". *p 가 int 라는 뜻으로 읽어라
p = &x;            // p 에 x 의 주소를 넣는다
printf("%d", *p);  // 10. p 가 가리키는 곳의 값 (역참조, dereference)
*p = 20;           // x 를 20으로 바꾼다 (p 를 통해)
printf("%d", x);   // 20
```

메모리 그림:
```
      x (주소 0x7ffe...a0)        p (주소 0x7ffe...a8)
   ┌──────────┐               ┌────────────────┐
   │    20    │  ◄────────────│   0x7ffe...a0  │
   └──────────┘               └────────────────┘
   "값을 담는 집"              "x의 주소를 담는 집"
```

`./bin/06_basics` 가 `x`, `&x`, `p`, `&p`, `*p` 를 전부 찍어 이 그림을 확인시켜 줍니다.

---

## 2. 포인터의 크기와 타입

- **모든 포인터의 크기는 같습니다** (64비트 시스템에서 8바이트). `int *`, `char *`, 함수 포인터 전부.
- 그런데 왜 타입이 필요한가? **두 가지** 때문입니다:
  1. **역참조할 때 몇 바이트를 읽을지**: `*(int *)p` 는 4바이트, `*(char *)p` 는 1바이트.
  2. **포인터 산술의 보폭**: `p + 1` 은 "`sizeof(*p)` 바이트 뒤" (7장).

---

## 3. `NULL` — "아무것도 안 가리킴"

```c
int *p = NULL;         // 습관: 포인터는 항상 초기화. 안 하면 "쓰레기 주소"(wild pointer)
if (p != NULL) *p = 1; // NULL 검사 후 사용. if (p) 로 줄여 써도 됨
*p = 1;                // p 가 NULL 이면 크래시 (SIGSEGV). 보통 "0x0 주소 접근"
```

- `malloc` 실패, 못 찾은 검색 결과, 리스트의 끝 등을 `NULL` 로 표현합니다.
- **규칙**: 포인터를 반환하는 함수를 쓰면 즉시 `NULL` 인지 확인. 포인터를 `free` 한 뒤엔
  `p = NULL;` 로 만들면 double free / use-after-free 를 조기에 크래시로 바꿔 줍니다 (8장).

---

## 4. `const` 와 포인터 — 위치가 전부다

**오른쪽에서 왼쪽으로** 읽으세요. `const` 는 바로 왼쪽 것을 잠급니다 (`*` 왼쪽이면 그 앞).

```c
const int *p;          // p 는 "const int 로의 포인터". *p 변경 불가, p 재대입은 가능
int * const p = &x;    // p 는 "int 로의 const 포인터". p 재대입 불가, *p 변경은 가능
const int * const p;   // 둘 다 불가
```

| 선언 | `*p = 5;` | `p = &y;` | 쓰임새 |
|---|---|---|---|
| `int *p` | OK | OK | 일반 |
| `const int *p` | ✗ | OK | **함수 인자**: "나는 이걸 안 바꿔요" (예: `strlen(const char *)`) |
| `int *const p` | OK | ✗ | 드묾 |
| `const int *const p` | ✗ | ✗ | 드묾 |

> **실무 습관**: 함수가 포인터로 받은 데이터를 수정하지 않으면 `const` 를 붙이세요.
> 호출자에게 보장이 되고, 컴파일러가 실수를 잡아 주고, 문자열 리터럴도 넘길 수 있습니다.

## 5. 이중 포인터 (`T **`) — "포인터를 바꾸고 싶을 때"

함수가 **호출자의 포인터 자체**를 바꾸려면 그 포인터의 주소를 받아야 합니다.

```c
void alloc_string(char **out) {     // char * 를 바꾸고 싶으니 char ** 를 받음
    *out = malloc(16);
    strcpy(*out, "hello");
}

char *s = NULL;
alloc_string(&s);                   // s 의 주소를 넘김
printf("%s\n", s);                  // "hello"
free(s);
```

같은 이유로:
- `int argc, char **argv` — `argv` 는 "문자열들의 배열"을 가리킴 (문자열 = `char *`).
- 연결 리스트에서 `head` 를 바꾸는 함수는 `Node **head` 를 받습니다 (15장).
- `./bin/06_double_ptr` 가 "왜 `char *` 로는 안 되는지"를 실패 케이스와 함께 보여 줍니다.

## 6. `void *` — 타입을 지운 포인터

```c
void *p;              // "무언가의 주소". 역참조 불가 (몇 바이트인지 모름), 산술 불가(표준)
int x = 5;
p = &x;               // 어떤 포인터든 void * 로 암묵 변환됨 (캐스트 불필요)
int *ip = p;          // 다시 꺼낼 때도 캐스트 불필요 (C에서. C++은 필요)
*(int *)p = 10;       // 쓰려면 원래 타입으로 캐스트
```

- `malloc` 은 `void *` 를 반환합니다 → 어떤 타입 포인터에도 대입 가능.
- `qsort`, `memcpy` 등 "타입 무관" 함수의 인자가 `void *` 입니다 (14장).
- **`malloc` 결과를 캐스트하지 마세요** (`(int *)malloc(...)`). C에선 불필요하고,
  `<stdlib.h>` 를 안 includ 한 실수를 가려 버립니다.

## 7. 포인터가 위험해지는 순간 (미리 보기)

| 상황 | 결과 | 방어 |
|---|---|---|
| 초기화 안 한 포인터 역참조 | 랜덤 주소 접근 → 크래시/오염 | 선언 시 `= NULL` 또는 즉시 유효값 |
| `NULL` 역참조 | SIGSEGV | 사용 전 검사 |
| `free` 후 사용 (UAF) | UB, 조용히 오염되기도 | `free` 후 `= NULL` |
| 스택 지역 변수 주소를 함수 밖에서 사용 | UB (5장) | `static`/힙/호출자 버퍼 |
| 배열 경계 밖 포인터 역참조 | UB (7장) | 길이를 함께 다루기 |
| 타입 불일치 역참조 (strict aliasing) | UB (16장) | `memcpy` 사용 |

이 표가 실무 C 버그의 90%입니다. 8·16·17장에서 하나씩 도구로 잡아 봅니다.
