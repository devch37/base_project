# 04. 제어 흐름

> 목표: `if/switch/for/while` 의 함정, `switch` 폴스루, `break/continue`,
> 그리고 **`goto` 가 실제로 정당한 유일한 패턴**.

---

## 0. 초등학생 버전 비유

제어 흐름은 **보드게임의 규칙 카드**입니다.
- `if` = "빨간 칸이면 한 번 쉬어라"
- `switch` = "주사위 눈에 따라 다른 칸으로" (단, C의 switch는 카드를 안 멈추면 다음 칸까지 계속 읽는다 — 폴스루)
- `for/while` = "도착할 때까지 반복"
- `break` = "이 미니게임 즉시 종료"
- `goto` = "이 칸으로 순간이동" (남용하면 게임판이 엉망이 되지만, 딱 한 가지 정당한 용도가 있다)

---

## 1. `if` 함정

```c
if (x = 5) { ... }        // 대입! 항상 참. 원래는 x == 5.  → -Wparentheses 로 경고
                          // 방어: if (5 == x)  (Yoda 조건) 또는 컴파일러 경고 신뢰
if (a < b < c) { ... }    // (a < b) 는 0/1, 그걸 c 와 비교. 수학과 다름
if (flag == TRUE) { ... } // FALSE(0)가 아닌 모든 값이 참. flag 가 2면? if (flag) 로 써라
if (0.1 + 0.2 == 0.3)     // 거짓 (2장). 실수는 == 로 비교하지 마라

if (cond)
    do_a();
    do_b();               // 들여쓰기와 무관하게 do_b()는 항상 실행. 중괄호를 항상 써라
```

> **실무 스타일**: 한 줄짜리라도 `if` 본문에 `{ }` 를 씁니다.
> (Apple의 "goto fail" SSL 취약점이 바로 중괄호 없는 `if` + 중복된 `goto` 한 줄 때문이었습니다.)

## 2. `switch` — 폴스루와 점프 테이블

```c
switch (c) {              // c 는 정수 타입만 (int, char, enum). 문자열/실수 불가
case 'a':
case 'e':
case 'i':
case 'o':
case 'u':
    vowels++;
    break;               // break 없으면 다음 case 로 "떨어짐"(fall through)
case '\n':
    lines++;
    /* fall through */    // 의도적 폴스루는 이렇게 주석으로 명시 (-Wimplicit-fallthrough)
case ' ':
    whitespace++;
    break;
default:
    other++;
    break;               // default 에도 break 를 (나중에 case 를 추가할 때 안전)
}
```

- `case` 라벨은 **컴파일 타임 상수**여야 합니다. 변수 불가.
- `case` 안에서 변수를 선언하려면 블록으로 감싸야 합니다: `case 1: { int x = ...; break; }`
  (안 그러면 "switch case에서 초기화를 건너뛴다" 에러/경고)
- 컴파일러는 case가 촘촘하면 `if-else` 사슬 대신 **점프 테이블**로 최적화합니다 (O(1)).

`./bin/04_switch` 가 문자 분류기로 폴스루를 보여 줍니다.

## 3. 반복문

세 가지는 거의 상호 변환 가능합니다.

```c
for (int i = 0; i < n; i++) { ... }   // 초기화; 조건; 증감 을 한눈에 → 가장 흔함
while (cond) { ... }                   // 반복 횟수를 모를 때
do { ... } while (cond);               // 최소 한 번은 실행해야 할 때 (입력 검증 루프 등)
```

### 함정

```c
for (int i = 0; i < n; i++);           // 세미콜론! 본문이 빈 루프. → -Wempty-body
for (size_t i = n - 1; i >= 0; i--)    // size_t 는 항상 >= 0 → 무한 루프 (2장)
while (fgets(buf, sizeof buf, fp))      // 좋음: NULL 반환 시 종료
for (int i = 0; i < n; i++) {
    for (int i = 0; i < m; i++) { ... } // 안쪽 i 가 바깥 i 를 가림 → -Wshadow
}
```

### `break` / `continue`
- `break` — 가장 안쪽의 `switch` 또는 반복문 하나를 탈출.
- `continue` — 이번 반복을 건너뛰고 다음 반복으로 (for 의 증감식은 실행됨).
- **중첩 루프를 한 번에 탈출**하려면? C에는 `break 2` 가 없습니다 → 플래그 변수, 함수로 분리,
  또는 `goto`.

## 4. `goto` — 유일하게 정당한 패턴: 정리(cleanup)

여러 자원을 순서대로 얻고, 중간에 실패하면 **얻은 것만 역순으로 해제**해야 할 때.
`goto` 없이 쓰면 해제 코드가 갈래마다 중복되고, 하나 빠뜨리면 누수입니다.

```c
int process(const char *path) {
    int rc = -1;
    FILE *fp = NULL;
    char *buf = NULL;

    fp = fopen(path, "rb");
    if (!fp) goto out;                 // 아직 얻은 게 없음 → 바로 나감

    buf = malloc(4096);
    if (!buf) goto close_fp;           // fp 는 얻었으니 닫아야 함

    if (fread(buf, 1, 4096, fp) == 0) goto free_buf;

    /* ... 실제 작업 ... */
    rc = 0;                            // 성공

free_buf:
    free(buf);
close_fp:
    fclose(fp);
out:
    return rc;
}
```

- 라벨은 해제 순서의 **역순**으로, 얻은 자원마다 하나씩.
- 앞으로만 점프(forward goto). 뒤로 점프하는 goto는 거의 항상 잘못된 설계입니다.
- 리눅스 커널, SQLite, libcurl, OpenSSL 전부 이 패턴을 씁니다. 13장에서 다시 봅니다.

C++의 RAII, Go의 `defer`, Zig의 `defer` 는 전부 "이 패턴을 언어가 대신 해 주는 것"입니다.
C에는 없으니 손으로 합니다.
