# 15. 자료구조 직접 구현

> 목표: 동적 배열, 연결 리스트, 해시맵을 **직접** 구현하며 포인터·메모리·소유권을 종합한다.
> 오픈소스 C 프로젝트는 대부분 자체 자료구조를 가지고 있습니다(STL이 없으니까). 읽을 줄 알아야 합니다.

`examples/15/` 에 `da.h`, `list.h`, `hashmap.h` (헤더 라이브러리) + `15_demo.c` 가 있습니다.

---

## 0. 초등학생 버전 비유

- **동적 배열**: 늘어나는 기차. 자리가 꽉 차면 더 큰 기차로 통째로 이사(realloc).
  번호로 바로 찾기 빠름, 중간 삽입은 뒤를 다 밀어야 해서 느림.
- **연결 리스트**: 보물찾기. 각 쪽지에 "다음 쪽지 위치"가 적혀 있음. 중간에 쪽지 하나 끼우기 쉬움,
  N번째 쪽지 찾으려면 처음부터 따라가야 함.
- **해시맵**: 이름표를 숫자로 바꿔(해시) 그 번호의 사물함에 넣기. 이름만 알면 바로 찾음.
  단, 다른 이름이 같은 번호가 되면(충돌) 그 사물함에 여럿을 줄 세움.

## 1. 동적 배열 (`da.h`)

핵심은 8장의 `Vec` 과 같습니다. 여기서는 **매크로로 타입 제네릭**하게 만듭니다 (`stb` 스타일).

```c
typedef struct { int *data; size_t len, cap; } IntArray;

// 성장 전략: cap 이 0이면 8, 아니면 2배. amortized O(1) push.
// realloc 실패 처리, 소유권(da_free 로 해제) 문서화가 핵심.
```

실무 팁:
- `len` 과 `cap` 을 분리. `data` 는 `cap` 만큼 잡혀 있지만 유효 원소는 `len` 개.
- 원소를 삭제할 때 순서가 상관없으면 **마지막 원소를 그 자리로 옮기고 `len--`** (swap-remove, O(1)).
- 포인터를 저장해 두고 push 하면 realloc 후 **댕글링** — 인덱스로 저장하세요.

## 2. 연결 리스트 (`list.h`)

```c
typedef struct Node {
    int          value;
    struct Node *next;      // 자기 자신을 가리키는 포인터 (자기 참조 구조체)
} Node;

typedef struct { Node *head; size_t len; } List;
```

### `head` 를 바꾸는 함수는 이중 포인터 (6장 복습)

```c
// 맨 앞 삽입 — head 자체가 바뀌므로 List* 를 받아 lst->head 를 수정
int list_push_front(List *lst, int v) {
    Node *n = malloc(sizeof *n);
    if (!n) return -1;
    n->value = v;
    n->next = lst->head;
    lst->head = n;
    lst->len++;
    return 0;
}
```

### "이전 노드의 next 포인터"를 가리키는 이중 포인터 — 삭제의 우아한 관용구

```c
// 조건을 만족하는 첫 노드를 삭제. head 삭제와 중간 삭제를 분기 없이 처리.
void list_remove_if(List *lst, int target) {
    Node **pp = &lst->head;           // "다음 노드를 가리키는 자리"의 주소
    while (*pp) {
        Node *cur = *pp;
        if (cur->value == target) {
            *pp = cur->next;          // 이전의 next(또는 head)를 재배선
            free(cur);
            lst->len--;
            return;
        }
        pp = &cur->next;
    }
}
```

이 `Node **pp` 트릭은 리눅스 커널 코드에 자주 나옵니다. 처음엔 어렵지만 익히면 분기가 사라집니다.

### 소유권
- `list_free(lst)` 는 모든 노드를 순회하며 `free`. 순회 중에 `free` 하므로
  **`next` 를 먼저 저장**하고 free 해야 use-after-free 가 안 납니다.
- 리스트가 문자열 등 힙 데이터를 담으면 노드 free 전에 그 데이터도 free (깊은 해제).

## 3. 해시맵 (`hashmap.h`) — 문자열 키 → 값

가장 배울 게 많은 자료구조입니다. 구현 결정들:

| 결정 | 이 예제의 선택 | 대안 |
|---|---|---|
| 해시 함수 | FNV-1a (짧고 분포 good) | djb2, SipHash(공격 방어), xxHash(속도) |
| 충돌 해결 | **체이닝**(버킷마다 연결 리스트) | 오픈 어드레싱(선형 탐사) — 캐시 친화적 |
| 키 저장 | 키 문자열을 **복사해서 소유** | 호출자가 수명 보장(위험) |
| 리사이즈 | load factor > 0.75 면 버킷 2배 + 전체 재해시 | 안 함(성능 저하 감수) |
| 크기 | 2의 거듭제곱 (`hash & (n-1)` 로 모듈로) | 소수 (`hash % prime`) |

```c
unsigned long fnv1a(const char *s) {
    unsigned long h = 1469598103934665603UL;   // FNV offset basis
    for (; *s; s++) { h ^= (unsigned char)*s; h *= 1099511628211UL; }  // FNV prime
    return h;
}
```

### 실무 함정
- **재해시 후 기존 노드 포인터는 무효**. 반환한 포인터의 수명을 문서화하세요.
- 키를 복사 안 하면, 호출자가 키 버퍼를 재사용/해제하는 순간 깨집니다.
- 삭제는 체이닝이면 쉬움(리스트에서 노드 제거). 오픈 어드레싱이면 tombstone 필요.
- 이터레이션 순서는 **없음**. 순서가 필요하면 별도 배열 유지.
- 악의적 입력이 전부 같은 버킷에 몰리면 O(n) → DoS. 웹 서버는 SipHash + 랜덤 시드 사용.

`./bin/15_demo` 가 세 자료구조를 모두 사용하고, `make asan NAME=15_demo` 로 누수 0을 확인합니다.

## 4. 언제 무엇을 쓰나

| 상황 | 자료구조 |
|---|---|
| 순서대로 쌓고 인덱스로 접근, 끝에서 추가/삭제 | 동적 배열 (기본값) |
| 앞/중간에서 자주 삽입·삭제, 순회 위주 | 연결 리스트 |
| 키로 빠른 조회 | 해시맵 |
| 정렬 상태 유지 + 범위 질의 | 이진 탐색 트리 / 정렬된 배열 |
| 우선순위 | 힙 (배열로 구현) |

> **기본은 동적 배열입니다.** 현대 CPU에서 연속 메모리 + 캐시가 이론적 복잡도를 자주 이깁니다.
> 연결 리스트는 "포인터 안정성이 필요하다", "원소가 크고 이동 비용이 크다"일 때만.
