# 05. 함수·스택 프레임·스코프·수명

> 목표: 함수를 호출하면 **스택에서 정확히 무슨 일이 일어나는가**, 변수의 **스코프(보이는 범위)** 와
> **수명(살아 있는 기간)** 은 어떻게 다른가, `static` 의 두 가지 뜻.

---

## 0. 초등학생 버전 비유

함수 호출은 **포스트잇 노트 묶음**입니다.
- 친구에게 심부름을 시키면(함수 호출), 친구는 새 포스트잇에 필요한 걸 적습니다 (지역 변수).
- 심부름이 끝나면 그 포스트잇을 **버립니다** (스택 프레임 소멸).
- 그런데 버린 포스트잇의 내용을 나중에 참조하면? (지역 변수 주소 반환) → 이미 다른 사람이
  그 포스트잇을 재활용해서 다른 걸 적어 놨을 수 있습니다. **쓰레기 값** 또는 **크래시**.

---

## 1. 함수 선언 vs 정의

```c
int add(int a, int b);            // 선언(프로토타입): "이런 함수가 어딘가 있다". 보통 헤더에.
int add(int a, int b) {           // 정의: 실제 코드. .c 파일에.
    return a + b;
}
```

- **선언 없이 함수를 호출하면?** C99부터는 **에러**입니다. (C89는 "암묵적으로 int 반환"으로 봐줬는데,
  이게 수많은 버그의 원인이었습니다.)
- `void f(void)` 와 `void f()` 는 **다릅니다**. 앞은 "인자 없음", 뒤는 (C23 전) "인자 정보 없음".
  항상 `(void)` 를 쓰세요.
- 인자는 **값으로 전달(pass by value)** 됩니다. 함수 안에서 매개변수를 바꿔도 호출자의 변수는 그대로.
  바꾸고 싶으면 **포인터를 넘깁니다** (6장).

---

## 2. 스택 프레임 — 호출 한 번의 작업 공간

함수를 호출하면 스택에 **프레임(activation record)** 하나가 쌓입니다. 프레임에는:

```
┌─────────────────────────┐  ← 높은 주소
│  호출자가 넘긴 인자 일부   │   (레지스터로 못 넘긴 것들; ABI마다 다름)
│  복귀 주소               │   (호출이 끝나면 어디로 돌아갈지)
│  저장된 프레임 포인터      │
│  이 함수의 지역 변수      │   ← 여기가 &local
│  임시 값, 정렬 패딩       │
└─────────────────────────┘  ← 낮은 주소 (스택은 아래로 자란다)
```

- 함수가 `return` 하면 프레임이 **통째로 사라집니다** (스택 포인터가 되돌아감).
  그 메모리는 즉시 다음 함수 호출이 재사용합니다.
- `./bin/05_stack` 이 재귀 호출마다 `&지역변수` 를 찍어, 프레임이 한 방향으로 쌓이는 걸 보여 줍니다.
- 재귀가 너무 깊거나 지역 배열이 너무 크면(`int big[1000000];`) **스택 오버플로우** → 크래시.
  큰 데이터는 힙(`malloc`)에 두세요.

## 3. 스코프 vs 수명 — 다른 개념

| | 스코프 (보이는 범위) | 수명 (메모리가 유효한 기간) |
|---|---|---|
| 블록 지역 변수 | 선언된 `{ }` 안 | 그 블록 실행 중 (`auto` 저장 기간) |
| `static` 지역 변수 | 선언된 `{ }` 안 | **프로그램 전체** (딱 한 번 초기화) |
| 전역 변수 | 파일 전체(또는 `extern` 으로 다른 파일) | 프로그램 전체 |
| `malloc` 한 메모리 | 포인터가 닿는 곳 어디든 | `free` 할 때까지 |

```c
int *counter(void) {
    static int count = 0;   // 수명: 프로그램 전체. 호출 간에 값 유지됨
    count++;
    return &count;          // OK! static 이라 함수가 끝나도 살아 있음
}

int *broken(void) {
    int local = 42;
    return &local;          // 위험! local 은 함수 종료 시 사라짐 → dangling pointer
}                           // -Wreturn-stack-address 로 경고, ASan 은 stack-use-after-return
```

`./bin/05_lifetime` 이 `static` 카운터와 "망가진" 버전을 나란히 보여 줍니다.
(`make asan NAME=05_lifetime` 로 돌리면 ASan이 use-after-return 을 잡습니다.)

## 4. `static` 키워드의 두 가지 뜻 (헷갈리지 마세요)

```c
static int x;             // (파일 스코프에서) "이 파일 밖에서는 안 보임" = internal linkage
                          //   → 11장. 다른 .c 의 같은 이름과 충돌 안 함. 헬퍼 함수에 필수.

void f(void) {
    static int y = 0;     // (함수 안에서) "수명은 프로그램 전체, 초기화는 한 번"
}
```

같은 키워드, 완전히 다른 의미. 위치로 구분하세요.

## 5. 매개변수 전달 정리

```c
void by_value(int x)      { x = 99; }        // 호출자 변수 안 바뀜
void by_pointer(int *x)   { *x = 99; }       // 호출자 변수 바뀜
void by_array(int a[], int n) { a[0] = 99; } // 배열은 포인터로 "붕괴"됨 → 원본 바뀜 (7장)

int n = 1;
by_value(n);    // n == 1
by_pointer(&n); // n == 99
```

큰 구조체(9장)를 값으로 넘기면 **통째로 복사**됩니다(느림). 보통 `const struct T *` 로 넘깁니다.

## 6. `inline`, 재귀, 가변 인자 (짧게)

- `inline` — "이 함수를 호출 지점에 펼쳐도 좋다"는 **힌트**. 강제 아님. 헤더의 작은 함수에 주로.
- 재귀 — C는 지원. 단 스택 깊이 = 재귀 깊이. 꼬리 재귀 최적화는 **보장 안 됨**(`-O2`에서 될 수도).
- 가변 인자 (`printf` 처럼) — `<stdarg.h>` 의 `va_list/va_start/va_arg/va_end`. 타입 안전성이
  전혀 없어 위험. `12_varargs.c` 에서 한 번만 다룹니다.
