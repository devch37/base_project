# 16. 정의되지 않은 동작(UB)과 이식성

> 목표: UB가 **왜 단순 크래시가 아닌지**, 대표 UB 카탈로그, strict aliasing,
> 엔디언, 정렬, 그리고 이식성 있는 코드를 쓰는 법.

---

## 0. 초등학생 버전 비유

보드게임 규칙서에 이렇게 적혀 있다고 해 봅시다:
> "말을 판 밖으로 움직이면 — **그다음은 어떻게 되든 우리 책임 아님.**"

그래서 어떤 심판(컴파일러)은 "말을 판 밖으로 옮기는 일은 **절대 안 일어난다**"고 가정하고
게임을 진행합니다. 여러분이 실수로 말을 판 밖에 놓으면, 심판은 그걸 "안 일어난 일"로 치고
엉뚱한 규칙을 적용합니다. 그래서 **말이 갑자기 사라지거나, 이긴 사람이 바뀌거나** 합니다.

이게 UB입니다. "크래시"가 아니라 **"컴파일러가 네 코드의 다른 부분까지 이상하게 바꿀 수 있음"**.

---

## 1. UB가 위험한 이유: 컴파일러의 "역방향 추론"

```c
int foo(int *p) {
    int x = *p;           // p 를 역참조 → 컴파일러: "p 는 NULL 이 아니구나"
    if (p == NULL)        // 위에서 이미 역참조했으니 이 검사는 "항상 거짓"
        return -1;        // → 이 줄이 통째로 삭제됨!
    return x + 1;
}
```

NULL을 넘기면 크래시가 아니라 **NULL 검사가 사라진 채로** 동작할 수 있습니다.
2015년 리눅스 커널의 실제 취약점(CVE-2009-1897)이 이 패턴이었습니다.

```c
int check(int a) {
    return a + 1 > a;     // 부호 있는 오버플로우는 UB → 컴파일러: "항상 참"
}                         // -O2 에서 이 함수는 그냥 return 1; 이 됨
```

`./bin/16_ub_overflow` 를 `-O0` 과 `-O2` 로 빌드해 결과가 달라지는 걸 확인하세요.
`make ubsan NAME=16_ub_overflow` 는 런타임에 정확히 잡아 줍니다.

## 2. 자주 만나는 UB 카탈로그

| # | UB | 예시 | 방어 |
|---|----|------|------|
| 1 | 부호 있는 정수 오버플로우 | `INT_MAX + 1` | `size_t`/`unsigned`, 사전 검사, `-ftrapv`/UBSan |
| 2 | 0으로 나누기 (정수) | `x / 0`, `x % 0` | 나누기 전 검사 |
| 3 | 널/유효하지 않은 포인터 역참조 | `*NULL`, `*(p after free)` | NULL 검사, free 후 =NULL |
| 4 | 배열 경계 밖 접근 | `a[n]`, `a[-1]` | 길이 동반, ASan |
| 5 | 초기화 안 한 값 사용 | `int x; return x;` | 항상 초기화, `-Wuninitialized` |
| 6 | 수명 끝난 객체 접근 | 지역 변수 주소 반환 (5장) | static/힙/호출자 버퍼 |
| 7 | 한 시퀀스에서 같은 객체 2회 수정 | `i = i++;`, `a[i]=i++` | 문장 분리 |
| 8 | 타입 불일치 역참조 (strict aliasing) | `*(float*)&int_var` | `memcpy` |
| 9 | 정렬 안 된 접근 | packed 구조체의 `int` 멤버 주소 | `memcpy`, 직렬화 함수 |
| 10 | `restrict` 계약 위반 | 겹치는 버퍼를 `restrict` 로 | 겹치면 `restrict` 빼기 |
| 11 | 문자열 리터럴 수정 | `char *s="x"; s[0]='y';` | `const char *`, 배열 복사 |
| 12 | `<ctype.h>` 에 음수 `char` 전달 | `isdigit(c)` where `c<0` | `isdigit((unsigned char)c)` |
| 13 | 이동/복사 크기 오류 | `memcpy(d,s,sizeof(s))` where s is a pointer | `sizeof(*s)`, 명시적 길이 |

### "구현 정의(implementation-defined)" 와 "미명세(unspecified)" 는 UB가 아님

- **구현 정의**: 컴파일러가 정하고 **문서화**함. 예: `char` 부호 유무, `>>` 음수 동작,
  `int` 크기. → 이식성 문제이지 "지뢰"는 아님.
- **미명세**: 여러 동작 중 하나인데 문서화 안 함. 예: 함수 인자 평가 순서. → 의존하지 마라.
- **UB**: 아무 일이나 일어날 수 있음. → 절대 피하라.

## 3. Strict aliasing — "타입으로 메모리를 두 번 보지 마라"

컴파일러는 **서로 다른 타입의 포인터는 같은 메모리를 가리키지 않는다**고 가정하고 최적화합니다.

```c
// UB: int 로 쓴 메모리를 float 로 읽음
float bit_cast_bad(int x) {
    return *(float *)&x;          // strict aliasing 위반 → 최적화 시 깨질 수 있음
}

// OK: memcpy 는 aliasing 규칙에서 자유롭다 (컴파일러가 알아서 최적화, 비용 0)
float bit_cast_ok(int x) {
    float f;
    memcpy(&f, &x, sizeof f);
    return f;
}

// OK: char* / unsigned char* 는 "모든 것을 alias 할 수 있다"는 예외
unsigned char *bytes = (unsigned char *)&some_struct;   // 바이트 검사는 항상 합법
```

예외: `union` 을 통한 접근은 C에서 관용적으로 허용됩니다(마지막에 안 쓴 멤버를 읽는 "type punning").
그래도 이식성/명확성 때문에 `memcpy` 를 권합니다.

## 4. 엔디언 (byte order)

```
uint32_t v = 0x11223344;

리틀 엔디언 (x86, ARM 기본): 메모리에  44 33 22 11   (낮은 바이트가 낮은 주소)
빅 엔디언 (네트워크, 일부 MIPS):        11 22 33 44
```

- **로컬 연산엔 신경 안 써도 됩니다.** `v + 1` 은 어느 쪽이든 동일.
- **파일/네트워크에 쓸 때** 문제됩니다. 해결: 바이트 단위로 직접 직렬화.

```c
void put_u32_be(unsigned char *p, uint32_t v) {     // 엔디언 무관, 이식성 100%
    p[0] = (unsigned char)(v >> 24);
    p[1] = (unsigned char)(v >> 16);
    p[2] = (unsigned char)(v >> 8);
    p[3] = (unsigned char)(v);
}
uint32_t get_u32_be(const unsigned char *p) {
    return (uint32_t)p[0] << 24 | (uint32_t)p[1] << 16 | (uint32_t)p[2] << 8 | p[3];
}
```

- `htonl`/`ntohl` (`<arpa/inet.h>`) 도 있지만 POSIX. 표준 코드엔 위 직렬화 함수를.
- 구조체를 `fwrite` 로 통째로 저장하지 마세요 — 엔디언 + 패딩 + 타입 크기가 기계마다 달라
  다른 컴퓨터에서 못 읽습니다.

`./bin/16_endian` 이 현재 기계의 엔디언을 보여 주고 직렬화를 검증합니다.

## 5. 이식성 체크리스트 (오픈소스 기여 시)

- [ ] `int` 가 32비트라고 가정하지 마라 → 크기 중요하면 `<stdint.h>`
- [ ] `long` 이 64비트라고 가정하지 마라 (Windows LLP64는 32비트)
- [ ] 포인터를 `int` 에 담지 마라 → `intptr_t`/`uintptr_t`
- [ ] `char` 가 signed라고 가정하지 마라 → 명시적으로 `signed char`/`unsigned char`
- [ ] 오른쪽 시프트가 산술이라고 가정하지 마라 (음수) → `unsigned` 로
- [ ] 구조체 레이아웃/패딩에 의존하지 마라 → 직렬화 함수
- [ ] 엔디언에 의존하지 마라
- [ ] 부동소수점 비트 정확도에 의존하지 마라
- [ ] `#include` 경로 대소문자 (macOS/Windows는 무시, Linux는 구분)
- [ ] `/` vs `\` 경로 구분자 → 라이브러리/매크로로 추상화
- [ ] GNU 확장(`__attribute__`, `typeof`, 중첩 함수)은 `#ifdef __GNUC__` 로 감싸거나 피하라
