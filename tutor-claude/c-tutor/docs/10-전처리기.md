# 10. 전처리기

> 목표: 전처리기가 **컴파일 전에 텍스트를 치환**한다는 것, 매크로의 함정,
> 헤더 가드, 조건부 컴파일, 그리고 언제 매크로 대신 `static inline`/`enum` 을 쓸지.

---

## 0. 초등학생 버전 비유

전처리기는 **찾아 바꾸기(Ctrl+H)** 로봇입니다. 문서를 컴파일러에게 주기 전에,
`#define` 목록을 보고 기계적으로 글자를 바꿉니다. **의미는 전혀 이해하지 못합니다.**
그래서 `#define SQUARE(x) x*x` 라고 하면 `SQUARE(1+2)` 를 `1+2*1+2`(=5)로 바꿔 버립니다.

---

## 1. 지시자 목록

| 지시자 | 하는 일 |
|---|---|
| `#include "f.h"` / `<f.h>` | 파일 내용을 그 자리에 펼침. `""` 는 현재 디렉터리부터, `<>` 는 시스템 경로부터 |
| `#define NAME ...` | 텍스트 치환 (객체형 / 함수형 매크로) |
| `#undef NAME` | 정의 해제 |
| `#if` / `#ifdef` / `#ifndef` / `#elif` / `#else` / `#endif` | 조건부 컴파일 |
| `#error "msg"` / `#warning` | 컴파일 중단/경고 |
| `#pragma` | 컴파일러별 지시 (`#pragma once`, `#pragma pack`) |
| `#` (문자열화) / `##` (토큰 붙이기) | 매크로 안에서 |

---

## 2. 헤더 가드 — 절대 빠뜨리면 안 됨

같은 헤더가 두 번 `#include` 되면 타입 재정의 에러가 납니다. 방지:

```c
#ifndef MYLIB_COUNTER_H       // 프로젝트_경로_파일 형태로 유일하게
#define MYLIB_COUNTER_H
/* ... 헤더 내용 ... */
#endif /* MYLIB_COUNTER_H */
```

또는 (비표준이지만 사실상 모든 컴파일러 지원):

```c
#pragma once
```

이 코스와 11장 예제는 전통적 `#ifndef` 가드를 씁니다 (이식성 100%).

## 3. 매크로 함정 5종 (`10_macros.c` 에서 전부 재현)

```c
// (1) 괄호 부족
#define SQUARE(x) x * x
SQUARE(1 + 2)          // 1 + 2 * 1 + 2 = 5  (원했던 건 9)
// 고침:
#define SQUARE(x) ((x) * (x))   // 인자와 전체를 모두 괄호로

// (2) 인자 다중 평가
#define MAX(a, b) ((a) > (b) ? (a) : (b))
MAX(i++, j++)          // i 또는 j 가 두 번 증가!
MAX(expensive(), 0)    // expensive() 가 두 번 호출

// (3) 세미콜론 / 블록 문제
#define LOG() printf("here\n")
if (x) LOG();          // OK
#define SWAP(a,b) t=a; a=b; b=t
if (x) SWAP(p, q);     // b=t 는 if 밖에서 항상 실행! → do-while(0) 로 감싸라
#define SWAP(a,b) do { int t=(a); (a)=(b); (b)=t; } while (0)

// (4) 이름 충돌 / 대문자 관례 무시
#define max 100        // <stdlib.h> 등의 식별자와 충돌 가능. 매크로는 UPPER_CASE

// (5) 타입 없음 → 디버거에서 안 보임, 타입 검사 없음
#define BUFSIZE 4096   // 차라리:  enum { BUFSIZE = 4096 };  (타입 있음, 디버거에 보임)
```

### 실무 규칙
- 상수는 매크로보다 `enum` 또는 `static const`.
- "짧은 함수"는 매크로보다 `static inline` (타입 검사, 다중 평가 없음, 디버깅 가능).
- 매크로가 정말 필요한 경우: 헤더 가드, 조건부 컴파일, `assert` 류(`__FILE__`/`__LINE__` 필요),
  제네릭 코드 생성(X-macro), 컴파일 타임 분기.

## 4. `#` 와 `##`

```c
#define STR(x)  #x                 // 인자를 문자열 리터럴로
#define XSTR(x) STR(x)             // 한 번 더 펼친 뒤 문자열화 (매크로 값을 문자열로)
STR(hello)      // "hello"
XSTR(__LINE__)  // "42"  (STR(__LINE__) 는 "__LINE__")

#define CONCAT(a, b) a##b          // 두 토큰을 하나로
#define MAKE_VAR(n)  int var_##n
CONCAT(foo, bar)   // foobar
MAKE_VAR(3);       // int var_3;
```

## 5. 조건부 컴파일 — 이식성과 빌드 옵션

```c
#ifdef __linux__
    #include <sys/epoll.h>
#elif defined(__APPLE__)
    #include <sys/event.h>          // kqueue
#elif defined(_WIN32)
    #include <winsock2.h>
#endif

#if defined(DEBUG) && DEBUG
    #define DBG(...) fprintf(stderr, __VA_ARGS__)
#else
    #define DBG(...) ((void)0)      // 릴리스에선 완전히 사라짐
#endif

#if __STDC_VERSION__ >= 201112L
    /* C11 이상: _Static_assert 사용 가능 */
#endif
```

유용한 미리 정의된 매크로: `__FILE__`, `__LINE__`, `__func__`(엄밀히는 매크로 아님),
`__DATE__`, `__STDC_VERSION__`, 컴파일러별 `__GNUC__`/`__clang__`.

## 6. X-macro — "데이터를 한 곳에, 코드를 여러 벌"

enum 과 그 이름 문자열, 테이블을 **한 목록에서** 생성하는 기법. 실무에서 종종 만납니다.

```c
#define COLOR_LIST(X) \
    X(RED,   "red")   \
    X(GREEN, "green") \
    X(BLUE,  "blue")

enum Color {
#define X(name, str) COLOR_##name,
    COLOR_LIST(X)
#undef X
};

static const char *color_name(enum Color c) {
    switch (c) {
#define X(name, str) case COLOR_##name: return str;
    COLOR_LIST(X)
#undef X
    }
    return "?";
}
```

새 색을 추가할 때 `COLOR_LIST` 한 줄만 고치면 enum과 이름 테이블이 동시에 갱신됩니다.
`./bin/10_xmacro` 참고.
