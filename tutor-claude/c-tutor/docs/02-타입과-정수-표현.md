# 02. 타입과 정수 표현

> 목표: 정수가 메모리에 **어떻게 저장되는가**(2의 보수), **암묵적 형 변환**의 규칙,
> 오버플로우가 왜 위험한가, 그리고 실무에서 어떤 정수 타입을 골라야 하는가.

---

## 0. 초등학생 버전 비유

자동차 주행거리계를 생각해 보세요. `999999` 다음은 `000000` 으로 돌아갑니다.
컴퓨터의 정수도 똑같이 **칸 수가 정해져 있어서**, 최댓값을 넘으면 한 바퀴 돌아 최솟값으로 갑니다.

그리고 컴퓨터는 음수를 표현할 때 이상한 트릭을 씁니다. "빼기"를 "특별한 방식의 더하기"로 바꾸는
트릭인데, 이걸 **2의 보수**라고 합니다. 덕분에 CPU는 덧셈 회로 하나로 뺄셈도 합니다.

---

## 1. 기본 타입과 크기

C 표준은 **정확한 크기를 정하지 않습니다.** "최소 이만큼"만 보장합니다.

| 타입 | 최소 보장 | 오늘날 64비트 리눅스/macOS에서 보통 |
|------|-----------|-----------------------------------|
| `char` | 1 바이트, ≥8비트 | 1바이트. 부호 유무는 **구현 정의**(x86은 signed, ARM은 unsigned인 경우도) |
| `short` | ≥16비트 | 2바이트 |
| `int` | ≥16비트 | 4바이트 |
| `long` | ≥32비트 | **리눅스/macOS 8바이트, Windows 4바이트** ← 이식성 함정 |
| `long long` | ≥64비트 | 8바이트 |
| `float` | — | 4바이트 (IEEE 754 single) |
| `double` | — | 8바이트 (IEEE 754 double) |
| 포인터 | — | 8바이트 (64비트 시스템) |

`./bin/02_sizes` 가 현재 시스템의 실제 크기를 출력합니다.

### 그래서 실무에서는 `<stdint.h>` 를 쓴다

크기가 중요하면(파일 포맷, 네트워크 프로토콜, 하드웨어 레지스터) **명시적 크기 타입**을 씁니다.

```c
#include <stdint.h>
int8_t   / int16_t  / int32_t  / int64_t     // 정확히 N비트, 부호 있음
uint8_t  / uint16_t / uint32_t / uint64_t    // 정확히 N비트, 부호 없음
size_t        // sizeof 의 결과 타입. 배열 인덱스/크기에 쓰는 "부호 없는" 타입
ptrdiff_t     // 두 포인터의 차이
intptr_t      // 포인터를 담을 수 있는 정수 (드물게 필요)
```

> **원칙**: "그냥 정수"면 `int`. "개수/크기/인덱스"면 `size_t`. "비트 폭이 중요"하면 `uintN_t`.

## 2. 2의 보수 (Two's Complement)

8비트로 설명합니다. 부호 없는 `unsigned char` 는 `0 ~ 255`.
부호 있는 `signed char` 는 **최상위 비트를 "부호"로 쓰지 않고**, 이렇게 정의합니다:

```
음수 x 의 비트 = (2^8 + x) 를 8비트로 자른 것

 0       = 0000 0000
 1       = 0000 0001
 127     = 0111 1111   ← 최댓값
-128     = 1000 0000   ← 최솟값 (127보다 하나 더 많음!)
-1       = 1111 1111
-2       = 1111 1110
```

왜 이렇게? **`a - b` 를 `a + (~b + 1)` 로 계산할 수 있어서**, 뺄셈 회로가 필요 없습니다.
`./bin/02_twos_complement` 가 이 계산을 직접 보여 줍니다.

핵심 결과:
- 부호 있는 정수의 최솟값은 최댓값보다 절댓값이 1 큽니다. `INT_MIN = -INT_MAX - 1`.
- `-INT_MIN` 은 **오버플로우** (표현 불가) → **UB**. `abs(INT_MIN)` 도 UB.

---

## 3. 오버플로우: 부호 있는 것과 없는 것은 완전히 다르다

| | 부호 없는 (`unsigned`, `size_t`) | 부호 있는 (`int`, `long`) |
|---|---|---|
| 오버플로우 시 | **정의됨**: 2^N 으로 나눈 나머지 (wrap around) | **Undefined Behavior** |
| `MAX + 1` | `0` | 정의 안 됨 (보통 `MIN` 이 되지만 믿으면 안 됨) |
| 컴파일러 최적화 | 감싸는 것으로 취급 | "오버플로우는 안 일어난다"고 가정하고 최적화 |

```c
unsigned int u = UINT_MAX;
u + 1;            // 0. 합법. 명세됨.

int i = INT_MAX;
i + 1;            // UB! 컴파일러가 i+1 > i 를 "항상 참"으로 최적화할 수도 있음
```

`./bin/02_overflow` 에서 `-O2 -fsanitize=undefined` 로 빌드하면 UBSan이 잡아냅니다.
16장에서 실제로 최적화가 코드를 삼키는 예를 봅니다.

### 실무에서 자주 나는 진짜 버그

```c
// 나쁨: size 가 0이면 size - 1 은 SIZE_MAX (엄청 큰 수) → 루프가 폭주
for (size_t i = 0; i <= size - 1; i++) { ... }

// 나쁨: a + b 가 오버플로우하면 검사 자체가 무의미
if (a + b > LIMIT) { ... }
// 좋음: 빼기로 바꿔서 검사
if (a > LIMIT - b) { ... }   // b <= LIMIT 이 보장될 때
```

## 4. 암묵적 형 변환 — "조용히 일어나는" 위험

C는 연산 전에 피연산자 타입을 자동으로 맞춥니다. 두 가지 규칙이 있습니다.

### (1) 정수 승격 (Integer Promotion)
`char`, `short`, 비트필드 등 `int` 보다 작은 타입은 연산 시 **자동으로 `int` 로 승격**됩니다.

```c
unsigned char a = 200, b = 100;
unsigned char c = a + b;   // a, b 가 int(300)로 승격 → 더함 → 300 → char 로 잘림 → 44
printf("%d\n", a + b);     // 300! (c 가 아니라 식 a+b 는 int)
```

### (2) 통상 산술 변환 (Usual Arithmetic Conversions)
서로 다른 타입을 연산하면 "더 넓은/부호 없는" 쪽으로 맞춰집니다.
**부호 있음 + 부호 없음 → 부호 없음** 이 함정입니다.

```c
int i = -1;
unsigned int u = 1;
if (i < u)  printf("음수가 작다\n");
else        printf("?!\n");     // 이게 출력됨! i 가 unsigned 로 변환되어 4294967295 가 됨
```

`./bin/02_conversions` 가 이 함정들을 모두 재현합니다.
`-Wconversion -Wsign-conversion` 을 켜면 컴파일러가 경고해 줍니다 (이 코스 Makefile에 포함).

## 5. 부동소수점 주의 한 스푼

- `0.1 + 0.2 != 0.3` 입니다 (이진 분수로 정확히 표현 불가). `==` 로 실수를 비교하지 마세요.
- `float` 는 유효숫자 약 7자리, `double` 은 약 15자리.
- 큰 수와 작은 수를 더하면 작은 수가 사라집니다 (`1e20 + 1 == 1e20`).
- 실무: 돈 계산은 실수 대신 **정수(센트 단위)** 로. 비교는 `fabs(a-b) < epsilon`.
