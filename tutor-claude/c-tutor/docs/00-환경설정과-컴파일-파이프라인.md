# 00. 환경 설정과 컴파일 파이프라인

> 목표: 컴파일러를 설치하고, **"소스 코드 한 줄이 어떻게 CPU가 실행하는 명령이 되는가"** 를 4단계로 그린다.

---

## 0. 초등학생 버전 비유

여러분이 한국어로 편지를 썼는데, 받는 사람은 영어만 압니다.
그래서 **번역가**에게 맡깁니다. 번역가는 이렇게 일합니다.

1. **준비** — 편지에 "여기에 자기소개 문단 넣기" 같은 메모가 있으면, 실제 문단으로 채웁니다. (전처리)
2. **번역** — 한국어 문장을 영어 문장으로 바꿉니다. (컴파일)
3. **타이핑** — 번역한 걸 타자기로 깔끔히 칩니다. (어셈블)
4. **묶기** — 여러 장을 순서대로 묶고, "3쪽 참고" 같은 걸 실제 쪽번호로 연결해 책으로 만듭니다. (링크)

C 컴파일러도 똑같이 4단계로 일합니다. 그리고 각 단계의 중간 결과물을 우리가 눈으로 볼 수 있습니다.

## 1. 컴파일러 설치

### macOS
```bash
xcode-select --install     # Apple clang + make + lldb 가 한 번에 설치됨
cc --version                # Apple clang version ... 이 뜨면 성공
```
> macOS의 `gcc` 는 사실 clang입니다. 이 코스는 둘 다에서 동작합니다.
> Valgrind는 Apple Silicon에서 안 돌아갑니다 → 대신 **AddressSanitizer**를 씁니다(17장).

### Linux (Debian/Ubuntu)
```bash
sudo apt update && sudo apt install build-essential gdb valgrind
cc --version
```

### Windows
- **WSL2 (권장)** — 위 Linux 명령을 그대로 사용.
- 또는 MSYS2 / MinGW-w64 로 `gcc` 설치.

### 확인
```bash
cd c-tutor
make run NAME=00_hello
```

## 2. 첫 프로그램: `examples/00/00_hello.c`

```c
#include <stdio.h>   // printf 의 "선언"을 가져온다 (11장에서 자세히)

int main(void) {     // 프로그램의 시작점. OS가 여기를 호출한다.
    printf("안녕하세요, C의 세계에 오신 걸 환영합니다.\n");
    printf("이 문장은 컴파일러가 기계어로 번역해서, CPU가 직접 실행한 결과입니다.\n");
    return 0;        // 0 = 정상 종료. 셸에서 `echo $?` 로 확인 가능.
}
```

빌드하고 실행:
```bash
cc -std=c11 -Wall -Wextra examples/00/00_hello.c -o bin/00_hello
./bin/00_hello
echo $?          # 0  ← main 이 돌려준 값
```

## 3. 컴파일 파이프라인 4단계 — 직접 눈으로 보기

`cc a.c -o a` 한 방에 끝나는 것처럼 보이지만, 실제로는 이렇게 진행됩니다.

```
 00_hello.c
    │  ① 전처리 (preprocess)      cc -E
    ▼
 00_hello.i   ── #include 펼침, 매크로 치환, 주석 제거된 "순수 C"
    │  ② 컴파일 (compile)          cc -S
    ▼
 00_hello.s   ── 사람이 읽을 수 있는 어셈블리 (CPU 명령어)
    │  ③ 어셈블 (assemble)         cc -c
    ▼
 00_hello.o   ── 기계어 조각(오브젝트 파일). 아직 printf 주소가 비어 있음
    │  ④ 링크 (link)               cc (기본)
    ▼
 00_hello     ── 실행 파일. printf 는 C 표준 라이브러리에서 연결됨
```

직접 해 봅시다.

```bash
cd examples/00

cc -E 00_hello.c | tail -n 20        # ① stdio.h 가 펼쳐져 수백 줄이 됨
cc -S 00_hello.c -o 00_hello.s       # ② 어셈블리 생성
cat 00_hello.s                       #    call _printf 같은 게 보임
cc -c 00_hello.c -o 00_hello.o       # ③ 오브젝트 파일
nm 00_hello.o                        #    U _printf  ← U = Undefined(아직 미해결)
cc 00_hello.o -o 00_hello            # ④ 링크 → 실행 파일
./00_hello
```

### 각 단계가 하는 일

| 단계 | 입력 | 출력 | 하는 일 | 대표 에러 |
|------|------|------|---------|----------|
| ① 전처리 | `.c` | `.i` | `#include` 펼치기, `#define` 치환, `#if` 처리, 주석 제거 | `fatal error: 'foo.h' file not found` |
| ② 컴파일 | `.i` | `.s` | 문법 검사, 타입 검사, 최적화, 어셈블리 생성 | `error: use of undeclared identifier` |
| ③ 어셈블 | `.s` | `.o` | 어셈블리 → 기계어 바이트. 심볼 테이블 생성 | (거의 안 남) |
| ④ 링크 | `.o`들 + 라이브러리 | 실행 파일 | 함수/전역변수 주소 연결, 스타트업 코드 추가 | `undefined reference to 'foo'` / `duplicate symbol` |

> **실무 팁**: 에러 메시지를 보면 "몇 단계에서 났는지" 바로 알 수 있어야 합니다.
> `undefined reference` / `undefined symbol` → **링크(④) 에러**입니다. 함수 선언은 있는데
> 구현(.o나 라이브러리)이 안 붙은 것. `-l`, 소스 파일 누락, 오타를 의심하세요. (11장에서 반복)

## 4. 경고는 에러다

```bash
cc examples/00/00_warn.c -o /tmp/x                       # 조용히 컴파일됨 (위험)
cc -Wall -Wextra -Wpedantic examples/00/00_warn.c -o /tmp/x   # 경고 3개 출력
```

`examples/00/00_warn.c` 는 흔한 초보 실수 3개를 담고 있습니다. 경고 없이 컴파일하면
**멀쩡해 보이지만 런타임에 이상하게 동작**합니다. 이 코스의 Makefile은 항상
`-Wall -Wextra -Wpedantic -Wshadow -Wconversion` 을 켭니다. 실무에서는 여기에
`-Werror` (경고를 에러로 승격)까지 붙여 CI를 통과 못 하게 만듭니다.
