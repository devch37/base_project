# 07. 배열·포인터 산술·문자열

> 목표: **"배열은 포인터가 아니다"** 를 정확히 이해, 포인터 산술의 규칙, C 문자열(`'\0'`)의 실체와 함정.

---

## 0. 초등학생 버전 비유

배열은 **한 줄로 붙어 있는 사물함**입니다. 번호는 0부터.
- 사물함 10개를 배정받았으면(`int a[10]`), 쓸 수 있는 건 0~9번뿐입니다.
- 11번 사물함을 열면? C는 안 막습니다. 옆 반 사물함이거나, 벽이거나 — **UB**.
- "몇 번 사물함부터 시작인지"만 알면(첫 주소) 나머지는 계산으로 찾습니다. 그게 포인터 산술.

C 문자열은 **"끝에 마침표 스티커를 붙인 글자 사물함 줄"** 입니다. 스티커(`'\0'`)가 없으면
어디서 끝나는지 아무도 모릅니다.

---

## 1. 배열과 포인터는 "친척이지만 다르다"

```c
int a[5] = {10, 20, 30, 40, 50};

a          // 대부분의 문맥에서 &a[0] 로 "붕괴(decay)"됨. 타입: int *
a[2]       // *(a + 2) 의 문법 설탕. 그래서 2[a] 도 합법(!). 값: 30
&a         // 타입: int (*)[5]  — "배열 전체로의 포인터". &a + 1 은 20바이트 뒤
sizeof a   // 20 (5 * 4). 배열은 여기서 붕괴 안 함
```

### 배열이 포인터와 다른 점

| | 배열 `int a[5]` | 포인터 `int *p` |
|---|---|---|
| `sizeof` | 20 (전체 크기) | 8 (포인터 크기) |
| 재대입 | `a = ...` **불가** | `p = ...` 가능 |
| `&` | `int (*)[5]` | `int **` |
| 저장하는 것 | 원소들 자체 | 다른 곳의 주소 |

### 함수 인자에서는 항상 포인터로 붕괴

```c
void f(int arr[5]) { ... }   // 사실은 void f(int *arr). [5] 는 무시됨(문서용)
void f(int *arr) { ... }     // 위와 완전히 동일
// 그래서 함수 안에서 sizeof(arr) 는 8 (배열 크기 아님) → 길이를 따로 넘겨야 함
void g(const int *arr, size_t len);   // 실무 표준 시그니처
```

## 2. 포인터 산술 규칙

```c
int a[5];
int *p = a;          // = &a[0]
p + 1                // &a[1]. "1 * sizeof(int)" = 4바이트 뒤 (원소 단위!)
p + 3 - p            // 3 (ptrdiff_t). 포인터끼리 빼면 "원소 개수"
*(p + i) == p[i]     // 정의상 동일
++p                  // p 가 a[1] 을 가리키게

// 허용되는 범위: a[0] .. a[5] (마지막 원소 "다음"까지는 만들어도 됨, 역참조는 불가)
int *end = a + 5;    // OK (관용구: 순회 종료 조건)
while (p < end) { *p++ = 0; }

// UB: a - 1, a + 6 같은 주소를 "만드는 것"부터가 UB (역참조 안 해도!)
```

- 서로 다른 배열의 포인터를 비교/빼면 UB.
- `void *` 산술은 표준이 아님 (GCC 확장). `char *` 로 캐스트해서 바이트 단위 이동.

## 3. C 문자열: `char` 배열 + `'\0'`

```c
char s[] = "hi";        // { 'h', 'i', '\0' }  ← 크기 3! 널 종단자 포함
char t[2] = "hi";       // { 'h', 'i' }  ← '\0' 안 들어감! 이후 문자열 함수 쓰면 폭주
char *lit = "hi";       // "hi" 는 읽기 전용 정적 메모리. lit[0]='H' 는 UB(보통 크래시)
const char *lit = "hi"; // 이렇게 쓰는 게 옳다 (컴파일러가 수정을 막아 줌)
```

- `strlen(s)` = `'\0'` 전까지의 글자 수 = 2. **버퍼 크기가 아님**.
- 필요한 버퍼 크기 = `strlen + 1`.
- `'\0'` (숫자 0) vs `'0'` (문자, 아스키 48) vs `NULL`(포인터) vs `"0"`(문자열) — 전부 다릅니다.

### 문자열 함수와 안전성 (12·20장에서 심화)

```c
strcpy(dst, src);              // dst 가 충분히 큰지 검사 안 함 → 오버플로우 위험
strncpy(dst, src, n);          // n 바이트만. 하지만 src 가 길면 '\0' 을 안 붙임(!)
snprintf(dst, sizeof dst, "%s", src);  // 실무 권장: 항상 '\0' 종단, 크기 명시
strlcpy(dst, src, sizeof dst); // BSD/macOS. 안전하지만 표준 아님
```

## 4. 다차원 배열

```c
int m[3][4];             // 행 3, 열 4. 메모리에 연속(row-major): m[0][0], m[0][1], ..., m[1][0]
m[i][j] == *(*(m + i) + j) == ((int *)m)[i * 4 + j]
sizeof m                 // 48 = 3 * 4 * 4
void f(int m[][4], int rows);   // 첫 차원만 생략 가능. 나머지는 필수(오프셋 계산에 필요)
```

동적 2D 배열은 (a) `malloc(rows*cols*sizeof(int))` 후 직접 인덱싱 (권장), 또는
(b) 포인터의 배열 `int **` (행마다 따로 malloc) — 15장에서 다룹니다.

## 5. off-by-one — 가장 흔한 버그

```c
int a[10];
for (int i = 0; i <= 10; i++) a[i] = 0;   // i==10 에서 경계 초과! (<= 가 아니라 <)
for (int i = 0; i < 10; i++)  a[i] = 0;   // 올바름

char buf[8];
strcpy(buf, "12345678");                  // 8글자 + '\0' = 9바이트 필요 → 1바이트 초과
```
