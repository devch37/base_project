# 학습 가이드 — C를 "실무 수준"으로 익히는 전략

이 문서는 개별 문법이 아니라 **어떻게 공부하면 실무/오픈소스에 투입될 수 있는가**를 다룹니다.

---

## 1. C는 "작은 언어 + 거대한 책임"이다

파이썬이나 자바는 언어와 런타임이 여러분을 지켜줍니다. 배열 범위를 넘으면 예외가 나고,
안 쓰는 메모리는 GC가 치워 줍니다. **C는 그 보호막이 없습니다.**

- 문법 자체는 하루면 훑습니다. `for`, `if`, 함수, 구조체가 전부입니다.
- 진짜 학습량은 **"하면 안 되는 것"과 "메모리에서 무슨 일이 일어나는가"** 에 있습니다.
- 그래서 이 코스는 문법을 빠르게 지나가고, **포인터·메모리·UB·도구**에 시간을 씁니다.

비유하자면 C는 **안전벨트도 에어백도 없는 F1 자동차**입니다. 빠르고 정밀하지만,
운전자가 물리 법칙을 정확히 알아야 합니다. 이 코스의 목표는 그 물리 법칙을 몸에 익히는 것입니다.

---

## 2. 3단계 학습 루프

각 장마다 이 순서를 지키세요.

1. **읽기** — `docs/NN` 을 정독. 비유로 감을 잡고 개념을 정확히 이해.
2. **실행 + 관찰** — `examples/NN/` 코드를 컴파일해 돌리고, 주석을 읽고,
   `printf` 로 주소·크기·값을 찍어 봅니다.
3. **부수기** — 일부러 버그를 넣고 `make asan NAME=...` 으로 도구가 뭐라 하는지 봅니다.
   > 이 3번을 건너뛰면 실무에서 처음으로 세그폴트를 만나게 됩니다. 지금 만나 두세요.

## 3. 초보자가 반드시 겪어야 하는 "고전 실수" 체크리스트

아래를 **직접 재현**하고, 도구가 어떻게 잡아내는지 봤다면 이 코스의 절반은 끝난 겁니다.

| 실수 | 재현하는 장 | 잡는 도구 |
|------|------------|-----------|
| 배열 범위 초과 (off-by-one) | 07 | ASan: `heap-buffer-overflow` |
| `free` 후 사용 (use-after-free) | 08 | ASan: `heap-use-after-free` |
| `free` 두 번 (double free) | 08 | ASan: `attempting double-free` |
| `malloc` 후 `free` 안 함 (누수) | 08 | ASan/Valgrind: `leak of N byte(s)` |
| 초기화 안 한 변수 읽기 | 05 | UBSan/`-Wuninitialized`, Valgrind |
| `NULL` 역참조 | 06 | 세그폴트, ASan: `SEGV on unknown address 0x0` |
| 부호 있는 정수 오버플로우 | 02, 16 | UBSan: `signed integer overflow` |
| 반환한 지역 변수 주소 사용 | 05 | ASan: `stack-use-after-return` |
| `scanf`/`strcpy` 로 버퍼 넘침 | 20 | ASan: `stack-buffer-overflow` |
| 형식 문자열에 사용자 입력 (`printf(s)`) | 20 | `-Wformat-security` |

## 4. "실무 투입 가능"의 구체적 기준

이 코스를 마치면 아래를 **혼자서** 할 수 있어야 합니다. (22장 캡스톤이 이걸 검증합니다.)

- [ ] 세그폴트가 난 코어 덤프/스택 트레이스를 `lldb`/`gdb`로 열어 원인 줄을 찾는다
- [ ] 남의 C 프로젝트를 받아 `./configure && make` 또는 `cmake` 로 빌드하고 경고를 읽는다
- [ ] `malloc` 하는 함수를 보면 "누가 이걸 `free` 하지?"를 반사적으로 묻는다
- [ ] 헤더에는 무엇을, .c에는 무엇을 두는지 안다 (선언 vs 정의, `static`의 의미)
- [ ] 구조체 크기를 `sizeof` 없이 대략 계산하고, 왜 패딩이 들어가는지 설명한다
- [ ] `int` 오버플로우가 UB인 이유와, 언제 `size_t`/`uint32_t`를 써야 하는지 안다
- [ ] `qsort` 에 비교 함수를 넘길 수 있고, 함수 포인터 타입을 읽는다
- [ ] ASan/UBSan/Valgrind를 켜서 CI에 넣을 줄 안다
- [ ] 오픈소스에 패치를 낼 때 그 프로젝트의 C 표준 버전과 스타일을 맞춘다

## 5. 장별 소요 시간 가늠 (하루 1~2시간 기준)

| 구간 | 장 | 예상 |
|------|----|----|
| 기초 문법 (다른 언어 경험자면 빠름) | 00–04 | 2~3일 |
| **포인터·메모리 (핵심, 천천히)** | 05–08 | 5~7일 |
| 구조적 프로그래밍 | 09–13 | 4~5일 |
| 고급 (제네릭·자료구조·UB) | 14–16 | 4~6일 |
| 도구·빌드·동시성·보안 | 17–20 | 4~6일 |
| 오픈소스·캡스톤 | 21–22 | 3~5일 |

포인터 구간(05–08)에서 절대 서두르지 마세요. 여기가 무너지면 나머지가 다 흔들립니다.

## 6. 함께 보면 좋은 자료

- **K&R "The C Programming Language" (2판)** — 얇고 고전. 문체가 이 코스와 비슷합니다.
- **"Modern C" (Jens Gustedt)** — 무료 PDF. C11/C17 기준의 현대적 관점.
- **cppreference.com** — 표준 라이브러리 레퍼런스. `man 3 printf` 도 좋습니다.
- **"Computer Systems: A Programmer's Perspective" (CS:APP)** — 6~9장. 메모리/링킹의 바이블.
- **컴파일러 탐구**: <https://godbolt.org> — C가 어떤 어셈블리가 되는지 즉시 확인.
