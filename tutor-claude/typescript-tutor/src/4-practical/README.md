# 4단계: Practical — 실무 패턴

문법이 아니라 "설계"를 배우는 단계입니다. 1~3단계에서 배운 도구들을
실제 프로젝트에서 어떻게 조합하는지 봅니다.

## 학습 목표

- 일관된 API 응답 타입과 DTO ↔ 도메인 모델 분리를 설계한다
- 예상 가능한 실패를 예외가 아닌 `Result<T, E>` 값으로 다룬다
- "타입은 런타임에 사라진다"를 이해하고, 경계에서 데이터를 검증한다
- 타입을 먼저 설계하고 구현으로 내려가는 흐름을 체험한다

## 실무에서 바로 쓰는 규칙

1. **`as`를 쓰기 전에 멈춰라.** 외부 데이터(`unknown`)는 타입 가드나 검증기로 좁혀라.
2. **에러도 타입이다.** `throw new Error('...')`만 쓰지 말고, 실패 케이스를 유니온으로 나열하라.
3. **DTO와 도메인 모델을 분리하라.** 네트워크 경계에서 한 번만 변환하고, 내부에서는 도메인 모델만 다뤄라.
4. **`switch`에는 `default: assertNever(x)`를 넣어라.** 나중에 케이스가 늘면 컴파일러가 잡아준다.
5. **타입을 먼저 설계하라.** 함수 시그니처와 도메인 타입을 먼저 쓰면 구현이 따라온다.
